# 07 · 实现路线图

从零写一个 MRP 模拟器的推荐顺序。这是 PymRP 实际走过的路（A 级），
每个阶段都有**客观验收标准**——过不了就不要进下一阶段，否则返工成本极高。

---

## 阶段 0：准备

需要的东西：

| 项 | 说明 |
|---|---|
| ARM 执行引擎 | 推荐 Unicorn（QEMU 内核，pip install unicorn） |
| 显示层 | pygame / SDL / 任意能贴一张 240×320 RGB565 图的东西 |
| `cfunction.ext` | 331 KB ARM 运行时，从 vmrp 发行包获取（**没有它什么都跑不了**） |
| 一个真实 `.mrp` | 推荐 `dsm_gm.mrp`（官方启动器，最能暴露问题） |
| GB 字库 | `gb16.uc2` 等，随发行包 |

> ⚠️ 没有运行时文件时，唯一能做的是阶段 1-3（用自己手写的 ARM 机器码做单元测试）。

## 阶段 1：执行引擎 + 内存布局

做：8 MB 线性内存，三段映射（代码 0x80000 / 栈 0x180000 / 堆 0x280000），
能加载一段 ARM 代码并执行。

**验收**：手写这段机器码，执行后 R0 = 0x2A：

```arm
mov r0, #0x15        ; 21
mov r1, #0x15        ; 21
add r0, r0, r1       ; 42 = 0x2A
bx  lr
```

顺便验证 Thumb 模式切换（`blx` 低位地址 = Thumb）可用——mythroad 两种模式都用。

## 阶段 2：函数表（syscall 机制）

做：见 [02 §3](02-运行原理-虚拟机怎么跑MRP.md#3-核心机制用内存地址当-syscall-号)。
146 个 `mr_table` 槽 + 51 个 `dsm_require_funcs` 槽，每槽写自身地址，code hook 拦截。

**验收**：手写 ARM 码 `ldr r3,[pc,#x]; blx r3` 调用 `mr_getTime` 槽位，
宿主日志能看到被拦截，R0 返回合理值，且执行流回到 `blx` 的下一条。

## 阶段 3：内存分配器 + 最小 API

做：first-fit 堆 + 这几个 API：

```
mr_mem_get / mr_mem_free          堆
mr_open/close/read/write/seek     文件（直接映射宿主目录 + 路径沙箱）
mr_getTime / mr_getDatetime
mr_getScreenInfo
```

**验收**：ARM 码依次调 `mr_mem_get(64)` → 写入 → `mr_open` 写文件 →
`mr_open` 读回比对，全部成功。

## 阶段 4：ext 启动链路

做：加载 `cfunction.ext` 到 0x80000 → 表基址写 0x80000 → 从 0x80008 执行 →
处理 `_mr_c_function_new` 回调（P 写回 0x80004）→ `mr_dsm_init()`。

**验收**：`dsm_init()` 返回 0，日志里能看到 ext 主动调了一批 `mr_*`
（典型：`mr_open("mythroad/...")` 找字库和配置）。这里最容易暴露
"哪个 API 必须真实现"——ext 会按固定顺序试探。

## 阶段 5：跑通启动器

做：`mr_start_dsm("dsm_gm.mrp", "start.mr", 0)` + 帧缓冲呈现 + timer 循环。

**验收**：窗口里出现「应用列表」菜单，图标和文字完整。

> 这一步的常见失败：
> - `code=3006`：工作目录不对，启动器要用相对路径 `mythroad/xxx.mrp` 枚举游戏；
> - 白屏：帧缓冲地址/跨度不对；
> - 崩在乱七八糟的地址：函数表槽位内容写错（必须写自身地址）。

## 阶段 6：按键

做：`mr_event(MR_KEY_PRESS/RELEASE, key, 0)` 投递。

**验收**：按 ↓ 光标移动、按 OK 进入子菜单、能从菜单启动推箱子并看到标题画面。

> ⚠️ 键值枚举顺序反直觉：`数字0-9 → * → # → 方向 → POWER(16) → 软键 → SEND → SELECT(20)`。
> 把 SELECT 写成 16 = 每次按确定都在发挂机键，应用当然不理你。
> 全表见 [09 常量速查](09-常量速查.md)。

## 阶段 7：触摸直通

做：`mr_event(MR_MOUSE_DOWN/MOVE/UP, x, y)` 原样转发窗口坐标（240×320 坐标系）。

**验收**：直接读事件内存块，确认 `(code,x,y)` 三元组原样到达。
别期望画面有反应——这批应用不处理触摸（见 [00 §3.2](00-这套系统是什么.md#32-按键不是触摸)）。

## 阶段 8：声音

做：见 [05 声音与流媒体专题](05-声音与流媒体专题.md)。顺序：
`mr_playSound`（MIDI/WAV）→ `mr_plat(102/103)` PCM → `mr_platEx(201x)` 状态机。

**验收**：ARM 端到端调用三个真实槽位能拿到非零 PCM；
FFT 验证合成音准（A4 = 440 Hz ± 20 音分）。

## 阶段 9：工程化

- **测试金字塔**：自检（硬编码 ARM 码调每个关键槽位）→ 模块探针（音频/触摸/按键）→
  真实包端到端（启动器进游戏）；
- **统计**：API 调用计数（找出被频繁调用但未实现的）；
- **截图通道**：headless 渲染出 PNG，回归测试比对哈希；
- **打包**：pyz / 单文件，注意 `__file__` 在 zip 里不可用。

## 各阶段大致工作量参考（单人，D 级）

| 阶段 | 占比 | 说明 |
|---|---|---|
| 1–3（引擎+syscall+最小 API） | ~25% | 机制一旦通，后面全是填表 |
| 4–5（启动链路） | ~15% | 但 **调试密度最高**，一个地址错全盘崩 |
| 6–7（输入） | ~10% | 逻辑简单，坑在常量 |
| 8（声音） | ~20% | MIDI 合成占大头，可先只做 WAV |
| 9（工程化） | ~30% | 测试与工具决定后续维护性 |

## 常见死胡同（提前避让）

- ❌ 想自己写 Mythroad 层替代 `cfunction.ext` → 331 KB ARM 逆向，无穷深；
- ❌ 想解释 `.mr` 字节码而不是跑 ARM → 解释器在 ext 里，`.mr` 是给它的中间码；
- ❌ 用固定 tick 数判断"跑通了" → 必须以画面内容为准（截图哈希）；
- ❌ 在 hook 里做重活（如每次指令都查表）→ 只 hook 函数表所在页。
