# 00 · 这套系统是什么

## 1. 三个名字，三层东西

刚接触时最容易被三个名词绕晕，先把关系钉死：

| 名词 | 是什么 | 在哪 |
|---|---|---|
| **MRP** | 应用包的文件后缀，也是这套应用生态的代称 | 你手上的 `.mrp` 文件 |
| **Mythroad**（神话之路） | 应用运行时层：解释字节码、管资源、提供 `mrc_*` 应用 API | 真机 ROM 里的 `cfunction.ext`（331 KB ARM 代码），或随包携带 |
| **SkyEngine** | 底层虚拟机核心：执行 ARM 指令、提供 `mr_*` 系统 API | 真机 ROM，由斯凯（SKY-MOBI）移植到各家平台 |

依赖方向是**从上到下单向**：

```
.mrp 应用
   │  调用 mrc_*（应用级 API：mrc_open / mrc_drawBitmap / mrc_playSound ...）
   ▼
Mythroad 层（cfunction.ext）
   │  调用 mr_*（系统级 API：mr_open / mr_drawBitmap / mr_playSound ...）
   ▼
SkyEngine（虚拟机核心）
   │
   ▼
手机平台（MTK / 展讯 / ADI / TI / 高通 Brew）
```

**关键点：`cfunction.ext` 本身是 ARM 机器码**，不是字节码。它和你的 `.mrp` 跑在同一个
ARM 虚拟机上。所以你实现模拟器时，`cfunction.ext` 一个字节都不用改——只要 ARM 执行环境和
`mr_*` 接口齐备，它自己就能工作。

（A 级，实测：本项目把官方 `cfunction.ext` 原样加载到 0x80000 执行，成功完成初始化、
加载 `.mrp` 包、驱动 UI。见 [02 运行原理](02-运行原理-虚拟机怎么跑MRP.md)。）

## 2. 为什么它和 J2ME 不一样

同时代的 Java ME 是"Java 字节码 + 厂商 KVM"，MRP 走的是一条更土但更省的路：

| 维度 | J2ME (MIDP) | MRP / Mythroad |
|---|---|---|
| 包里装什么 | Java class 字节码 | `.mr` 自定义字节码 + `.ext` **ARM 机器码** |
| 运行时体积 | KVM 通常几百 KB ~ 数 MB | 整个引擎约 120 KB（手册原文自述，B 级） |
| 内存占用 | 堆受限，常见 200 KB~1 MB | 真机堆也很小，靠"够用就行"的设计 |
| 图形 | Canvas / GameCanvas，画笔模型 | **直接操作 RGB565 帧缓冲**，无合成器抽象 |
| 入口约定 | `MIDlet.startApp()` | `mrc_init / mrc_event / mrc_pause / mrc_resume` |
| 开发门槛 | 需要 Java 环境、签名、证书 | 一个 C 子集编译器 + 打包工具，草根开发者可上手 |
| 分发 | 运营商/应用商店，审核重 | 斯凯"冒泡"平台 + 预装 + 短信计费，铺得极快 |

正是"体积小、门槛低、渠道猛"这三点，让它在 MTK 功能机上赢下了国内市场。
代价是**生态封闭**：编译器私有、文档 CHM 化、平台接口靠厂商移植，最后几乎全lost。

## 3. 技术特征：几个必须知道的事实

### 3.1 屏幕是 RGB565 直写

应用拿到的是一块 `width × height × 2` 字节的缓冲，自己往上画像素。`mr_drawBitmap`
把一张位图 blit 上去，没有 alpha、没有图层（图层是平台侧的可选扩展，见
[06 图形与图层专题](06-图形与图层专题.md)）。

240×320 是最常见的规格（`0xF0` = 240 出现在每个 `.mrp` 头里，A 级实测）。

### 3.2 按键，不是触摸

绝大多数 MRP 应用是**按键驱动**的：方向键 + 左右软键 + 数字键 + 挂机/拨号键。
触摸屏接口（`mr_plat(1205)` 查询是否触摸屏、`MR_MOUSE_*` 事件）在协议里存在，
但 2008 年前后的应用基本不处理它。

所以：**点屏幕没反应是应用的问题，不是模拟器的 bug**。

### 3.3 声音是"喂数据"，不是"给路径"

`mr_playSound(type, data, dataLen, loop)` —— 第二个参数是**内存中的音频数据指针**，
不是文件名。应用自己把文件读进内存再交给平台。这和"播放器给个 URL"的思路完全不同。

（B 级，手册 `api/mr_playSound.md` 原文；本项目已按此实现，A 级验证。）

### 3.4 一切都是整数和指针

没有异常、没有对象、没有 GC（内存靠 `mr_mem_get` / `mr_mem_free` 显式管理）。
API 全部是 C 风格：参数走寄存器，返回值放 R0，失败返回负数。

### 3.5 一次只有一个应用在跑（但可以切后台）

`mr_start_dsm` 系列可以拉起子应用，形成"启动器 → 游戏"的嵌套结构。这也是为什么
官方启动器 `dsm_gm.mrp` 必须先跑起来，再从中选游戏——**直接启动游戏包会失败**，
因为游戏包内的主程序入口名和启动器期望的不一致。

（A 级实测：直接 `start_dsm("box.mrp")` 返回错误码 3006；经启动器则可正常加载。）

## 4. 生态版图（D 级，供参考）

- **应用类型**：小游戏（推箱子/俄罗斯方块/连连看/雷电类）、工具（天气/QQ/浏览器）、
  电子书、铃声图片下载器。
- **分发**：预装在方案商出货的机器里 + 斯凯自有平台下载 + 短信/流量计费。
- **规模**：公开资料常提到"覆盖数亿台手机"。具体数字已难核实，但"当年国产功能机上
  随处可见"是可以确认的体感事实。
- **结局**：智能机替代 + 平台方转型，生态在 2013 年前后迅速消失。编译器、打包工具、
  官方文档基本没有公开留存。

## 5. 今天还有哪些东西活着

| 资产 | 状态 |
|---|---|
| `.mrp` 应用文件 | 大量散落在老论坛/网盘，仍可下载（多为游戏合集） |
| `cfunction.ext` | 随 vmrp 等模拟器发行包流传，**必须与模拟器配套使用** |
| SkyEngine 手册（CHM） | 少量副本流传，已整理进本仓库 `docs/api/` |
| 开源模拟器 | [vmrp](https://github.com/vmrp/vmrp)（C + Unicorn）、mrpoid（Android）、本项目 pymrp（Python） |
| 官方编译器 | **已失传**，无法从源码编译出新 `.mrp` |
| 斯凯官方服务端 | 已停止 |

这意味着：**我们只能运行和改造现有 MRP，不能重新编译它们**。想修改行为只能靠
替换包内资源（图片/音乐，格式见 [03](03-MRP包格式规范.md)）或改模拟器侧实现。

## 6. 读完这篇你应该记住的三件事

1. `.mrp` 里是 **ARM 机器码 + 自定义字节码**，不是脚本，无法"解释"了事，必须真执行 ARM。
2. **Mythroad 层（cfunction.ext）是 ARM 代码**，模拟器不要试图重写它，只管提供 `mr_*` 接口。
3. MRP 的世界是 **RGB565 帧缓冲 + 按键事件 + 显式内存管理**，没有现代 GUI 那一套。
