# 16 · 皮肤系统与导航键区域扁平化

> **状态**：2026-11-10 按老板给的参考截图重做导航区，结论均为 A 级实测（逐像素采样 + 渲染对比）。
> 本文只讲**宿主层外观**（机壳、键盘），与 MRP 帧缓冲、mythroad 图形接口无关。

## 一、皮肤系统是什么

`PhoneUI` 把整台功能机画成一张 `(skin["width"], skin["height"])` 的 Surface，
几何、配色、键位全部来自 `runtime/skin.json`，代码里没有硬编码机型参数：

```
runtime/skin.json  ──load_skin()──►  PhoneUI(skin)
                                      ├─ _build_body()   机壳渐变/边框/听筒
                                      ├─ draw()          贴屏幕 Surface（240×320）
                                      ├─ _draw_nav()     圆形 D-pad
                                      ├─ _draw_key()     16 颗实体键
                                      └─ hit()           窗口坐标 → key id
```

首次运行时 `load_skin(path)` 发现文件不存在，会调 `build_default()` 写一份出来。
所以**换机型只改 JSON**，不用碰 Python。

`hit()` 的判定同样完全由 JSON 驱动：先算到 `nav.cx/cy` 的距离（`<=hole` 是 OK，
`<=r` 按主轴分四向），再逐个查 `keys[].rect`。因此改几何时，点击命中、
键值翻译、`key_at_name()`（Ctrl/Alt 软键映射）都不用改。

## 三、为什么要加高机身 30px

旧布局是 `300×660`：屏幕占 y 60–380（含边框到 386），数字键盘从 y 510 起，
留给导航区只有 **122px**。而按参考比例，圆盘直径要到 124px、四角按键 59px 高
（两排 + 间隙 = 59+59+11 = 129px）——**122px 装不下**。

硬塞只有两条路：把圆盘压到 100px 以下（比例失真），或者把按键压成扁条
（正是旧版被吐槽的样子）。所以选择加高机身：

| | 旧版 v1 | 新版 v2 |
|---|---|---|
| 机身 | 300×660 | **300×690** |
| 屏幕 | (30,60,240,320) | 不变 |
| 导航区 | y 386–508（122px） | **y 388–535（147px）** |
| 圆盘 | cx150 cy438 **r=38** hole=15 | **cx150 cy461 r=62 hole=23** |
| 四角按键 | 72×24 扁条，y 392 / 476 | **58×59 方块，y 396 / 466** |
| 数字键盘 | y0=510 | **y0=542** |
| 麦克风 | y=646 | y=676 |

圆盘边界 x 88–212，左列按键止于 x=80、右列起于 x=220，两侧各留 8px，
互不重叠。圆盘 y 399–523，上排按键 396–455、下排 466–525，圆盘比两排
整体略缩进 2–3px——和参考图一致。

## 四、绘制实现要点

### 4.1 按键（`phone.py::_draw_key`）

- 四种 `style`（`num` / `soft` / `send` / `end`）各自取一对 `*_top` / `*_bottom`，
  经 `_grad()` 做垂直渐变并用 `border_radius` 裁圆角；
- v2 把四角按键的圆角交给 `palette.key_radius`（9）、数字键仍用 `num_radius`（9），
  字号从 10 提到 13（方块变大了）；
- **去掉黑描边**，改成 `key_edge` 的 1px 淡边；数字键的蓝色背光轮廓只对
  `style == "num"` 保留；
- 按下态不再 `×1.28` 猛提亮，改 `×1.10 + 12`，再画一圈 `press_glow`
  （柔和浅灰 (214,222,234)，不是旧版的蓝色硬框）。

### 4.2 圆盘（`phone.py::_draw_nav`）

- 盘面 = `_grad(2r, 2r, nav_face_top, nav_face_bottom, r)`。
  `_grad()` 的圆形遮罩用 `border_radius=r` 实现，正好是圆；
- 只画一圈 `nav_edge` 淡边，**不做金属环、不做外圈黑边、不做内凹面**；
- 四向箭头是 `_arrow()` 画的实心等腰三角（顶点朝方向、底边反向 0.45×size），
  距圆心 `r × arrow_radius`（0.725），和 OK 圆、盘沿都留足空隙；
- 中央 OK 是**实心圆**（`ok_top → ok_bottom` 渐变 + 淡边 + "OK" 字），
  不再是旧版的空心圈轮廓；
- 按下态：对应方向箭头变 `highlight`，OK 圆整块提亮 + 文字变色。

### 4.3 旧皮肤 JSON 兼容

`load_skin()` 读到一个没有 `version: 2`、缺新调色键的旧 JSON 时，
会用 `build_default()["palette"]` **补齐缺失的键**（`palette.setdefault`），
不覆盖用户已有的自定义值。所以老皮肤仍能渲染，只是几何仍是旧布局——
想要新样式，删掉 `runtime/skin.json` 让程序重建即可。

## 五、自定义皮肤

```bash
# 1) 让程序按当前默认重建一份
rm runtime/skin.json
python run.py --headless --frames 1 --screenshot out/my_skin.png

# 2) 编辑 runtime/skin.json，改几何/配色/键位标签
# 3) 用 --skin 指定别的文件，便于多套机型并存
python run.py --skin skins/nokia.json "runtime/mythroad/box.mrp" --workdir runtime
```

改几何时记住三条约束（`tests/skin_probe.py` 会验）：

1. 圆盘与左右两列按键水平不重叠：`cx - r > 左列右边界`、`cx + r < 右列左边界`；
2. 所有 `keys[].rect` 在机身内，数字键盘在 `cy + r` 之下；
3. 屏幕 `screen` 段保持 `(30,60,240,320)`——`screen_pos()` 用它把窗口坐标
   换算成 MRP 坐标，动了会让触摸和 launcher 点击全部错位。

改配色只需动 `palette`，新增键名也能被 `.get()` / `setdefault` 兜住。
