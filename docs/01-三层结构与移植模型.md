# 01 · 三层结构与移植模型

## 1. 两个接口家族

SkyEngine 把"宿主（手机/模拟器）需要提供什么"拆成两套机制：

### 1.1 抽象移植接口（`mr_*`）

**固定签名、固定语义、VM 直接调用**。手册里的定义（B 级）：

> SkyEngine 抽象接口是 SkyEngine 根据移植的需要以及不同手机软件平台的共性，向下抽象的一套
> 需求接口函数，无论什么样的软硬件平台上，只要实现了这些接口函数，也就完成了平台上对
> SkyEngine 核心的支持。

特点：
- 函数名、参数、返回值全部固定，**不能改**；
- 覆盖文件、图形、内存、时间、网络、声音、UI 控件、事件等基础能力；
- 一个都缺不了，缺了就链接不上（真机）或调用失败（模拟器）。

### 1.2 扩展接口（`mr_plat` / `mr_platEx`）

手册原文（B 级）：

> `mr_plat` 和 `mr_platEx` 接口的主要目的是：**在不对 VM 进行修改的前提下，可以扩展 VM
> 支持的功能**，使得 VM 扩展功能不必再新增抽象接口。Mythroad 透明调用这个接口。

它们就是这套体系的"syscall 总入口"：

```c
int32 mr_plat  (int32 code, int32 param);
int32 mr_platEx(int32 code, uint8* input, int32 input_len,
                uint8** output, int32* output_len, MR_PLAT_EX_CB* cb);
```

差异：

| | `mr_plat` | `mr_platEx` |
|---|---|---|
| 输入 | 一个 int32 | 一段缓冲（`input` + `input_len`）+ 回调 `cb` |
| 输出 | 一个 int32 | 通过 `output`/`output_len` 返回一块数据 |
| 能力 | 只能传一个标量 | 可传结构体、可变长数据、异步回调 |
| 状态 | **已被官方标记为不推荐扩展** | **推荐**，新功能一律走它 |

手册明确说了不建议继续用 `mr_plat` 扩展：

> 在通常情况下，不再建议通过 `mr_plat` 来扩展，全部通过 `mr_platEx` 来扩展，这样做的好处
> 在于同一个模块的功能不会一部分 code 是通过 `mr_plat` 调用的，而另一部分的 code 是通过
> `mr_platEx` 来调用的。

**但历史遗留是现实**：`mr_plat` 仍有大量在用 code（PCM 环形缓冲、图层、相机、录音、
主题、信号强度……），实现模拟器时两套都得兜住。全量清单见
[`api/topics/`](api/topics/)，分册导航见 [04 接口地图](04-接口地图.md)。

### 1.3 `code` 编号是怎么分配的

没有统一注册表，只能从手册反推聚类规律（D 级推断，但样本足够）：

| 号段 | 领域 |
|---|---|
| `1`–`12` | 最早期杂项：虚拟键、CPU 频率、NES 存档、按键音、存储位置 |
| `1001`–`1020` | 网络与系统：socket 状态、SIM、状态栏图标、PCM、背光 |
| `1100`–`1117` | 短信与 APN / 主题 |
| `1201`–`1231` | 设备信息：字宽字高、语言、随机数、小区 ID、文件指针、WIFI |
| `1302`–`1333` | 声音音量、**MTK 图层系统**、状态栏、TODO |
| `1391` | 后台运行能力查询 |
| `1401`–`1406` | 文件浏览器（本地 UI） |
| `201x`–`225x` | **多媒体播放器**（`x` = 媒体类型，见 [05](05-声音与流媒体专题.md)） |
| `2500`–`2509` | 相机（camera） |
| `2700`–`2704` | 录音 |
| `3001`–`3015` | 图片/GIF 解码、DMA 刷屏、MTK 资源绘制 |
| `4001`–`4043` | 动感芯片、电话本 |
| `5001`–`5101` | 时间、闹钟、天气、软键文本 |
| `6000`–`6005` | 桌面气泡框、待机界面、异步转后台 |
| `0x90001`–`0x90002` | 时区、支持语言列表 |

## 2. 调用约定：一切都是 C ABI

### 2.1 参数与返回值

- 全部是 **C 风格 32 位整数/指针**；
- 参数按 ARM AAPCS 走 `r0,r1,r2,r3`，超出部分进栈；
- 返回值放 `r0`：`>= 0` 表示成功或有效值，负数表示错误。

### 2.2 返回值语义

| 常量 | 值 | 含义 | 注意 |
|---|---|---|---|
| `MR_SUCCESS` | `0` | 成功 | |
| `MR_FAILED` | `-1` | 失败 | |
| `MR_WAITING` | `2` | 异步操作进行中，需轮询或等回调 | 网络/短信/解码常用 |
| `MR_IGNORE` | `1` | 不支持 / 无需关心 | **注意是 1，不是 3** |

> ⚠️ `MR_IGNORE = 1` 这一点我最初写错过一次（写成 3），导致判断"平台不支持"的分支全歪。
> 依据：`mrpoid2018` 与 `vmrp` 两份 `mrporting.h` 均为 `#define MR_IGNORE 1`。
> （C 级，双源码交叉验证）

### 2.3 `MR_PLAT_VALUE_BASE` —— 最容易踩的语义陷阱

手册原文（B 级）：

> 考虑到 `mr_plat`/`mr_platEx` 接口会使用 `MR_SUCCESS`、`MR_FAILED`、`MR_WAITING`、
> `MR_IGNORE` 等返回值来表示接口本身的执行情况，定义偏移 `MR_PLAT_VALUE_BASE = 1000`，
> 当 `mr_plat`/`mr_platEx` 需要返回（有限）整型数值时，加上偏移量 `MR_PLAT_VALUE_BASE`。

也就是说同一个 int32 返回值承担**两重语义**：

```c
ret == MR_SUCCESS           // 调用成功，但没有数值要返回
ret == 1000 + n             // 调用成功，业务数值是 n
ret <  0                    // 调用失败
```

而且手册自己就警告了这个设计的危险：

> 这样会使返回值具有多重功能，而有可能 1000 加上这个值刚好就是 `MR_SUCCESS` 等里面的一个，
> 将会导致错误。

**实现时要注意**：`1001`（= `1000+1`）既是"成功且值为 1"，又和 IDLE 状态码撞车。典型例子
是多媒体播放器的 `209x` 查询状态，返回 `1000 + PLAY_STATE`，其中 `1001` 表示 IDLE。
判断时先按接口文档的约定解释，**不要**统一用 `ret >= 0` 当成功。

### 2.4 回调（`MR_PLAT_EX_CB`）

`mr_platEx` 的 `cb` 参数用于异步结果回传。真机上平台拿到数据后回调虚拟机里的函数指针，
虚拟机会把控制权交回应用。模拟器实现时最省事的做法是**同步化**：在 `mr_platEx` 内部把
结果准备好，直接 `return MR_SUCCESS`，把 `cb` 忽略；只有严格依赖异步时序的应用才会出问题。

（D 级建议，实践中未遇到必须异步的场景。）

## 3. 启动时序

这是实现模拟器时最容易搞错的地方。完整链条（A 级，实测于 PymRP + vmrp）：

```
1. 宿主：初始化内存布局、函数表、事件缓冲
2. 宿主：把 cfunction.ext 加载到 CODE_ADDRESS(0x80000)
3. 宿主：把 mr_table 基址写入 CODE_ADDRESS + 0
4. 宿主：从 CODE_ADDRESS + 8 以 ARM 模式开始执行
        └─ 这是 ext 的入口，它调用 mr_c_function_load(1)
5. ext 回调 _mr_c_function_new(P, extHelper)
        ├─ P：ext 的全局结构体指针（含 ER_RW 数据段）
        └─ extHelper：事件入口地址
   宿主把 P 写到 CODE_ADDRESS + 4（约定！ext 靠 *(load_addr - 4) 取回自己的 P）
6. 宿主：mr_dsm_init()          → 完成虚拟机初始化
7. 宿主：mr_start_dsm("xxx.mrp", "cfunction.ext", 0)
        └─ 返回 0 表示成功；应用开始跑 mrc_init
8. 循环：mr_timer() 按毫秒节拍推进
        mr_event(code, p0, p1) 投递按键/触摸/定时器事件
9. 退出：mr_event(MR_EVENT_EXIT) 或应用自己 mr_exit
```

### 3.1 事件码

| 常量 | 值 | 用途 |
|---|---|---|
| `DSM_INIT` | `-100` | 虚拟机初始化完成 |
| `MR_START_DSM` | `-99` | 启动子应用 |
| `MR_PAUSEAPP` | `-98` | 暂停 |
| `MR_RESUMEAPP` | `-97` | 恢复 |
| `MR_TIMER` | `-96` | 定时器节拍 |
| `MR_EVENT` | `-95` | 普通事件（按键/触摸/网络回调） |
| `VMRP_VER` | `20210701` | 版本戳（vmrp 用） |

（C 级：出自 `mythroad/include/dsm.h`，且实测事件投递按此值工作。）

### 3.2 为什么"直接启动游戏包"会失败

`start_dsm` 的第二个参数是**包内入口文件名**。启动器 `dsm_gm.mrp` 的入口是 `start.mr`，
普通游戏包是 `cfunction.ext`（包内自带一份我的克隆）。名字对不上就报错：

```
read file cfunction.ext err code=3006
```

这不是 bug，是包结构的必然结果。正确用法：**先跑启动器，再从菜单里选应用**。

（A 级实测：`start_dsm("box.mrp","cfunction.ext")` → 3006；
经 `dsm_gm.mrp` 菜单选择 → 成功渲染推箱子标题画面。）

## 4. 平台版本号规则

用于标识"这台机器是什么平台、支持哪些接口"。32 位整数，按十进制分段（B 级，手册原文）：

| 十进制位 | 11 以上 | 10 | 9 | 8–7 | 6–5 | 4–1 |
|---|---|---|---|---|---|---|
| 含义 | 未使用 | 预留 | 新旧规则 | 平台编码 | 平台内版本号 | 基线版本号 |

### 4.1 第 9 位：新旧规则

- `0` = 老版本（2008-01-18 之前）
- `1` = 新版本

### 4.2 平台编码（两位十进制）

| 平台 | 编码 | 平台 | 编码 |
|---|---|---|---|
| MTK | `01` | MSTAR | `08` |
| SPREADTRUM（展讯） | `02` | VIA | `09` |
| NXP | `03` | Symbian | `10` |
| WinCE | `04` | linux | `12` |
| Anyka | `05` | 未定义 / BREW | `13`（手册自身冲突） |
| ADI | `06` | coolsand | `14` |
| TI | `07` | | |

### 4.3 平台内版本号（MTK 芯片套系）

| 芯片 | 标识 | 芯片 | 标识 |
|---|---|---|---|
| MT6219 | 1 | MT6230 | 6 |
| MT6223P / MT6223 / MT6223P_S00 | 2 | MT6227 / MT6227D | 7 |
| MT6225 | 3 | MT6235 | 8 |
| MT6226 / MT6226M / MT6226D | 4 | MT6229 | 9 |
| MT6228 | 5 | MT6253B | 10 |
| | | MT6238 / MT6239 / MT6268 | 11 / 12 / 13 |

展讯：6600d=1, 6600m=2, rocky=3, nile=4, 6600h=5, mocor=6, 6600L=7
MSTAR：8528=1, 8535=2, 8538=3

### 4.4 基线版本号（4 位十进制）

| 位 | 含义 |
|---|---|
| 第 4 位 | `1` = 双卡双待机型，`0` = 否 |
| 第 2–3 位 | **接口集版本**，对应下面的接口跟踪表 |
| 第 1 位 | `2` = 不支持后台运行，其他值未定义 |

## 5. 接口跟踪表：能力是按版本逐批加的

这张表解释了一个常见困惑：**同一份代码在不同机器上行为不同**，因为老机型根本没实现新接口，
`mr_plat` 会返回 `MR_IGNORE`。移植/模拟时可以用来判断"这个 API 该不该期待它存在"。

| 接口集 | 新增能力 |
|---|---|
| `x01x` | 6225 JPEG 解码、PNG 解码、后台运行、改进的 cell id 获取、**文件指针位置** |
| `x04x` | 选择 SIM、追加发送短信 |
| `x08x` | 录音、拍照、设置屏保/背景、接收触摸屏 move 事件、非本地 UI 电话本 |
| `x09x` | 设置新短信是否提示、获取 T 卡状态 |
| `x10x` | 短信接口、获取网络 ID |
| `x11x` | 获取短信中心号码、副卡短信、**流媒体接口（fsal.c）** |
| `x15x` | 获取信号强度、申请内部 cache、申请大内存、后台播放、APN 设置、连 WAP 时选 SIM、**`mr_playSound` 音量可控** |
| `x16x` | 对动感芯片（加速度传感器）的支持 |

实战含义（D 级推断，但很有用）：

- 想放 BGM 又要求 `mr_plat(1302)` 音量可控 → 至少 `x15x`；
- 想用 `mr_platEx(201x)` 流媒体播放器 → 至少 `x11x`；
- 想读文件当前位置（`mr_plat(1231)`）→ 至少 `x01x`；
- 老机型（`x00x`）上这些都会返回 `MR_IGNORE`，应用必须自己降级。

## 6. 移植者要实现的清单

按依赖顺序，一个最小的可用移植层需要：

1. **内存**：`mr_mem_get` / `mr_mem_free`（+ 可选大内存/cache 扩展）
2. **文件**：`mr_open/close/read/write/seek/getLen/remove/rename/mkDir/rmDir/find*`
3. **时间**：`mr_getTime` / `mr_getDatetime` / `mr_sleep`
4. **显示**：`mr_drawBitmap` / `mr_getScreenInfo` / `mr_getCharBitmap`（+ 帧缓冲直写）
5. **事件**：`mr_event` 投递、`mr_timer` 节拍、pause/resume/exit
6. **系统信息**：`mr_info` / `mr_getUserInfo` / 平台版本号
7. **声音**：`mr_playSound` / `mr_stopSound`（+ PCM 或流媒体扩展）
8. **网络**：`mr_socket` 全家桶（不联网的应用可以返回 `MR_IGNORE`）
9. **UI 控件**：`mr_menu*` / `mr_edit*` / `mr_text*` / `mr_dialog*`（纯软件实现即可）
10. **其余 `mr_plat` / `mr_platEx`**：按需，未实现的统一返回 `MR_IGNORE`（**不要返回失败**，
    否则某些应用会当成致命错误退出）

> 第 10 条的返回值选择很重要：`MR_IGNORE` 表示"这台机器没这功能"，应用通常会降级；
> `MR_FAILED` 表示"有功能但执行失败"，应用可能直接弹错误框或退出。
