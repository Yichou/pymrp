# MRP / Mythroad / SkyEngine 知识库

这是一份**抢救性整理**的技术资料：把这套 2004–2011 年间装机量以亿计的国产功能机应用体系，从
散落的 CHM 手册、二进制样本、开源模拟器源码里还原成可读、可复现、可实现的知识体系。

> 为什么值得抢救：MRP 是**中国自己的功能机应用生态**，曾覆盖数亿台 MTK/展讯/ADI 平台手机，
> 今天它的编译器、发行渠道、官方文档、开发者社区几乎全部消失。剩下的只是一堆 `.mrp` 二进制
> 文件和几份被转存多次的 CHM。如果没人把它讲清楚，十年后没人再能读懂这些文件。

## 一、三十秒看懂这套东西

```
 你的 .mrp 文件
      │  内层：gzip 压缩的若干条目
      │  其中 .mr 是 mythroad 字节码（\x1bMRP 头，Lua 5.1 格式），.ext 是 ARM 机器码
      ▼
 mythroad 层（cfunction.ext，ARM 机器码，331 KB）
      │  解释 .mr 字节码、管理资源、提供 mrc_* 应用级 API
      │  自己通过 mr_open/mr_read 读 .mrp 包
      ▼
 mythroad 宿主层（mythroad.c，9679 行 + src/ 改名版 Lua 5.0 解释器）
      │  mr_* 系统级 API（文件/图形/声音/网络）、MRPG 解包、事件循环 mr_timer、
      │  插件链 MRF_RunFile、内存模型 mr_mem_get/free
      ▼
 手机硬件（MTK 6225/6226/6235 等）
```

**一句话**：`.mrp` 不是脚本，里面装的是 ARM 机器码和字节码；模拟器要做的就是
**造一个 ARM 执行环境 + 一套系统 API**，然后把这个包喂进去。

> **我们模拟器当前的位置**：`cfunction.ext` 这一层直接可用（Unicorn 跑 ARM 码），
> 但**最底下那层 mythroad 宿主是我们用 Python 手写的**（`api/impl.py` 1502 行）——
> 也就是在"猜"官方语义。想彻底对齐，得用 `mythroad.c` 源码自编译一个真虚拟机。
> 详见 [26 自编译 mythroad 虚拟机方案](26-自编译mythroad虚拟机方案.md)。

**只想跑起来**：`00` → `07` → 用现成实现（[pymrp](../mrp_emu/) 或 vmrp）

## 四、资料可靠性分级

文档里每个结论都标注来源等级，请按需采信：

| 等级 | 标记 | 含义 |
|---|---|---|
| A | 实测 | 在真实样本/真实运行中验证过，附有验证方法 |
| B | 手册 | 出自 SKY-MOBI 官方 CHM 手册原文 |
| C | 源码 | 出自 vmrp / mrpoid 等开源模拟器实现 |
| D | 推断 | 由前几项推理得出，未直接验证，文中会写明 |

凡是没有标注的叙述，都是 D 级推断——请当作线索而非结论。

## 五、这份知识库怎么维护

生成脚本在仓库根目录：

```bash
python tools/extract_manual.py   # CHM 文本 -> docs/api/ 逐页 Markdown + INDEX
python tools/build_docs.py       # 按主题聚合成 docs/api/topics/ 分册
```

手写正文（`00`–`20`）不受脚本影响，可自由编辑。手册原文永远以 `docs/api/` 为准，
正文只是导读与总结。
