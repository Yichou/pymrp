# 18 高分屏缩放、退出收尾与崩溃隔离

> 2026-11-10 晚。老板一次提了三个问题：
> ① 「开启了缩放的 window 上显示模糊，适配下高分屏缩放」；
> ② 「mr_exit() 调用之后没有停止背景音乐，联网文件句柄全部要关闭，然后退回系统界面」；
> ③ 三国志 `PC=0x2FF282` 野指针崩溃。
>
> 前两个是模拟器自己的锅，已经修干净；第三个是应用侧缺陷，模拟器做兜底隔离。

---

## 一、缩放为什么糊：两个独立的放大

老板看到的「模糊」其实是**两次放大叠在一起**：

| # | 来源 | 现象 | 修法 |
|---|---|---|---|
| 1 | Windows 系统 DPI 缩放（125% / 150%） | 进程不感知 DPI 时，系统把整个窗口当位图拉伸 | 进程级 `PER_MONITOR_AWARE_V2` |
| 2 | 我们自己的 `smoothscale` 拉伸 | 300×690 的成品图被插值放大 | 机壳改成 **矢量重绘**，不拉伸成品图 |

### 1.1 DPI 感知

```python
# cli.py
def enable_dpi_awareness() -> str:
    if sys.platform != "win32":
        return "n/a"
    try:
        import ctypes
        try:   # Win10 1703+：PER_MONITOR_AWARE_V2
            ctypes.windll.user32.SetProcessDpiAwarenessContext(ctypes.c_void_p(-4))
            return "per-monitor-v2"
        except Exception:
            pass
        try:   # Win8.1+
            ctypes.windll.shcore.SetProcessDpiAwareness(2)
            return "per-monitor"
        except Exception:
            pass
        ctypes.windll.user32.SetProcessDPIAware()
        return "system"
    except Exception:
        return "failed"
```

必须在**创建窗口之前**调用（`pygame.display.set_mode` 之后就晚了）。
本机实测返回 `per-monitor-v2`。

副作用要注意：感知之后 pygame 报上来的鼠标坐标变成**物理像素**，窗口尺寸也得按
物理像素给 —— 这正好和下面的矢量重绘一致。

### 1.2 整数倍 + 矢量重绘

非整数倍缩放（比如 1.27x）会把每个像素打散到半个物理像素上，`smoothscale`
柔、`scale` 糙，怎么选都糊。所以：

1. 缩放系数只取**整数倍**（`--scale` 会 round 到整数；自动模式取
   `floor(min(可用高/机身高, 可用宽/机身宽))`，最小 1）；
2. 机壳**按 k 倍矢量重绘** —— 不是把 300×690 的成品图拉伸：

```python
# ui/skin.py
def scaled_skin(skin: dict, k: int) -> dict:
    """几何整体放大 k 倍（只动位置/尺寸/圆角，不动配色）。
    screen.w/h 是 MRP 的逻辑分辨率（240x320），不能放大。"""
```

```python
# ui/phone.py
class PhoneUI:
    def __init__(self, skin: dict, scale: int = 1) -> None:
        self.k = max(1, int(scale))
        skin = scaled_skin(skin, self.k)
        ...
```

`PhoneUI` 里所有硬编码常量（字号、线宽、圆角内缩、麦克风间距…）都乘 `self.k`，
绘制结果直接就是 `300k × 690k` 的物理像素表面，`cli` 不再对整帧做
`smoothscale`，事件坐标也直接用窗口坐标。

**屏幕内容例外**：MRP 的 240×320 是低分辨率位图（游戏画面、系统 UI），
仍然走 `smoothscale` 放大 —— 那本来就是"低分辨率内容铺在大屏上"的效果，
插值反而更顺滑。要彻底高清就得给 `Launcher` 也做矢量渲染，那是另一件事。

对比图：`mrp_emu/out/zoom_compare.png`（左=整图拉伸，右=矢量重绘）。

## 二、mr_exit() 之后为什么音乐还在响

**根因一句话：`vm.exited` 只被设置，从来没有被消费。**

```
mr_exit()  ->  vm.exited = True        （impl.py）
                       ↓
                 没有任何人看它       （cli.py 从来没检查过）
```

所以应用退出后：

- 背景音乐继续放（老应用还会以为声音没停而反复重播）；
- 网络 socket 一直挂着；
- 文件句柄一直占着 —— **句柄号会被下一次会话复用**，MRP 侧可能读到别的文件；
- 界面停在应用里，回不到系统界面。

### 2.1 统一收尾 `App.shutdown_session()`

```python
# app.py
def shutdown_session(self, reason: str = "") -> dict:
    """退出 / 崩溃时的统一收尾：停声音、关网络、关文件句柄。"""
    info = {"reason": reason, "sockets": 0, "files": 0, "audio": False}
    self.net.close_network()      # 关掉所有 socket 槽
    info["sockets"] = len(self.net.slots)
    info["files"] = self.fs.close_all()     # 关掉所有文件句柄
    self.audio.stop_all()         # 停音效 / PCM 流 / 流媒体 / 背景音乐
    info["audio"] = True
    return info
```

配套新增：

| 位置 | 新增 | 作用 |
|---|---|---|
| `fs.py` | `VirtualFs.close_all()` | 关所有文件句柄与目录句柄，返回关掉的数量 |
| `audio/mixer.py` | `AudioEngine.stop_all()` | 停一次性音效、PCM 流、流媒体播放器、背景音乐（`mixer.music` + 全部 channel） |
| `audio/media.py` | `MediaRack.release_all()` | 释放所有流媒体播放器与多通道背景音 |
| `cli.py` | `teardown_session()` | 调 `app.shutdown_session()` 并打印统计 |

### 2.2 退出后要回系统界面

`cli.py` 主循环每帧检查：

```python
if mode == "mrp" and mrp_loaded and vm.exited:
    log("[vm] 应用调用 mr_exit()")
    back_to_home("应用退出（mr_exit）")
    continue
```

`back_to_home()` 现在先做收尾再切界面：

```python
def back_to_home(reason: str = "返回待机桌面") -> None:
    teardown_session(reason)
    if launcher:
        mode = "launcher"
        launcher.go("home")
        launcher.toast("已返回待机桌面")
        update_caption()
```

```

[vm] 应用调用 mr_exit()

[teardown] 应用退出（mr_exit）
```

## 三、三国志 `PC=0x2FF282` 崩溃：根因在应用侧，模拟器做隔离

老板日志：

```
[vm] 执行异常 Invalid memory read (UC_ERR_READ_UNMAPPED) @ PC=0x2FF282
[vm] 非法访问:@0xCE875143(4B) PC=0x2FF282
[vm] timer 异常: Invalid memory read (UC_ERR_READ_UNMAPPED)
```

### 3.1 复现

本地 `runtime/mythroad/301034_240320_gsgz.mrp`（三国志）在**按键交互**下
900 帧内稳定复现，同一段代码：

| | 老板日志 | 本地复现 |
|---|---|---|
| PC | `0x2FF282` | `0x2FF282` |
| 非法读地址 | `0xCE875143` | `0xCE87512B`（差 0x18，同一段数据的不同偏移） |

崩溃前应用连续打开失败 5 个运行时数据文件：
`plugins/kbill.mrp`、`plugins/addons.mrp`、`system/userinfo.sys`、
`system/userinfo2.sys`、`gsgz/user.l` —— 斯凯服务器停运后拿不到。

### 3.2 定位过程

1. **反汇编 `0x2FF282`**：ARM 和 Thumb 两种模式解出来都是同一条 `b` 序列，
   说明那片内存**是数据不是代码**（switch 编译出的跳转表）—— PC 跳进了数据，
   即**间接跳转的目标算错了**。
2. **排除 `mr_platEx(1204)`**：对照 mrpoid 的 `dsm.c::dsmSwitchPath`，
   我们的 Y 分支（返回 `c:/<work_path>`、`output` 写指针、`output_len` 写
   `strlen`）与官方语义一致；1204 不是元凶。
3. **排除资源缺失**：把 5 个缺失文件都造出假内容再跑，**野指针值一模一样**
   （`0xCE87512B`），说明不是"读到空数据后算错"，是确定性的代码路径。
4. **排除模拟器实现**：崩的是应用自己的代码段（MRP 加载到 0x2A5xxx 之后的
   堆区），不是我们的 API 实现。

**结论**：应用在缺少斯凯运行时数据的条件下，间接跳转目标算错，跳进自己的
数据表。属于应用侧缺陷（真机在同样数据缺失下大概率同样崩）。补资源需要
斯凯服务器，服务器已停运 —— 这条路暂时走不通。

### 3.3 模拟器侧该做的：崩溃隔离

既然修不了应用，就得保证它崩了**不带走整个模拟器**。以前只有 `timer`
包了 try/except，**按键路径完全裸调** —— `key_event` 一崩，进程直接退出。

现在所有虚拟机调用统一走 `guarded`：

```python
def guarded(desc: str, fn, *args):
    """包住虚拟机调用。MRP 是机器码，野指针随时会把 Unicorn 打断。"""
    try:
        return fn(*args)
    except Exception as exc:
        log(f"[vm] {desc} 异常: {exc}")
        back_to_home(f"{desc} 异常")
        return None
```

覆盖点：`key_event`（键盘/鼠标/触摸三种路径）、`touch_event`（DOWN/UP/MOVE）、
`timer`。崩了之后 → 记录原因 → 收尾（停声音/关 socket/关句柄）→ 退回系统界面，
用户还能接着玩别的应用。

端到端实测（`tests/crash_probe.py` 第 3 组，注入 timer 崩溃）：

```
[vm] timer 异常: Invalid memory read (UC_ERR_READ_UNMAPPED)
[teardown] 已关闭 1 个文件句柄、10 个 socket
[teardown] timer 异常
```

进程退出码仍是 0，且崩溃只发生一次（应用不再被驱动）。

## 五、边界

- `--scale` 现在只认整数倍；传 1.5 会被 round 成 1 或 2，想要精确值请直接
  改 `runtime/skin.json` 的几何。
- 屏幕内容（MRP 游戏画面、Launcher 的 240×320 UI）仍是位图插值放大，
  要完全高清得给 Launcher 也做矢量渲染。
- `PER_MONITOR_AWARE_V2` 之后鼠标坐标是物理像素；若将来支持窗口拖拽缩放，
  `screen_pos()` 的换算要跟着复核。
- 三国志这类依赖斯凯下发数据的应用仍然会崩（应用侧缺陷），只是不再带崩
  模拟器；补齐 `system/userinfo.sys`、`gsgz/user.l` 等真机预置文件才能根治。
