# 系统字库与宿主接口对齐：中文糊字 + 支付后崩溃

> 对象：① QQ 2007 登录界面中文糊成一坨；② 古董支付插件支付成功后野指针崩溃。
> 两条问题**同源**：宿主接口的返回值/字段语义与真机不一致。

---

## 一、问题一：中文糊成一坨

### 1.1 定位

放大截图后能分清三类元素：

| 元素 | 清晰度 | 来源 |
|---|---|---|
| QQ 企鹅 logo、QQ2007 logo | **清晰** | MRP 包内位图 |
| 输入框、勾选框、按钮 | **清晰** | 应用自己画的位图 |
| 「帐号」「密码」「记住密码」「隐身登录」 | **糊成一坨** | **系统点阵字库** |

只有最后一项糊 —— 说明问题不在宿主 UI 字体（`ui/launcher.py` 用微软雅黑，
本来就正常），而在 **MRP 应用在 ARM 侧自绘中文用的点阵字库**。

### 1.2 抓调用链

跑 `QQDSM2007.mrp` 抓日志：

```
[fs] open 'mythroad/system/gb16.uc2' mode=0x0 -> 1
[arm] [INFO]mr_open(mythroad/system/gb16.uc2,0) fd is: 1
[arm] [INFO]font load suc fd=1
```

应用启动第一件事就是打开 **`mythroad/system/gb16.uc2`**，运行时按
`seek(id * 32)` 取 16×16 的 1bpp 字模，**在 ARM 侧自己画中文**。
这条路径完全不经过宿主的 Python 字体 —— 所以换宿主字体（宋体/雅黑）
对它无效。

### 1.3 根因：我们自造的字库笔画粘连

早期 `fontgen.py` 的做法是：

```
64px 粗体渲染 -> smoothscale 缩到 16x16 -> 灰度阈值化
```

缩放会让**相邻笔画互相渗透**，缩完再阈值化，笔画之间就**粘死**了。

量化（墨迹率 = 黑像素占比，见 `fontgen.check_font_quality`）：

| 字库 | avg | max |
|---|---|---|
| 原厂 `fonts/gb16.uc2` | 0.236 | 0.316 |
| 早期自造版 | **0.367** | **0.594** ← 糊成黑块 |

### 1.4 关键发现：发行包里本来就有原厂字库

`runtime/mythroad/fonts/` 里躺着：

| 文件 | 大小 | 字模数 |
|---|---|---|
| `gb16.uc2` | 2 MB | 65536 |
| `sky16.uc2` | 2 MB | 65536 |

这些是**当年烧进固件的手工点阵字**，清晰度远高于任何系统字体缩放结果，
而且索引方式一致（Unicode 码位）。**我们此前在自己造一份更差的，把它盖住了。**

## 二、修复

### 2.1 优先复用原厂字库（`fontgen.ensure_uc2`）

三级策略：

1. 目标已存在 **且质量合格** → 直接用；
2. 发行包里有原厂字库 → **复制过来**（最清晰，且与真机一致）；
3. 都没有 → 用系统字体（宋体 → 微软雅黑）现场生成，作为兜底。

### 2.2 修正自造算法（`fontgen._glyph_mask`）

三个坑，逐个踩过：

| 坑 | 现象 | 解法 |
|---|---|---|
| 64px 渲染再缩放 | 笔画粘连成黑块 | **16px 直接渲染**，不缩放 |
| 读 RGB 通道 | 每个字都是实心方块（墨迹率 1.0） | `font.render(antialias=True)` 返回 **SRCALPHA** surface，抗锯齿在 **alpha 通道**，RGB 全是 255 |
| 二次裁剪 | 行宽变成 14/15，位序错乱成乱码笔画 | `_fit_mask` 保证输出**严格 16×16**；`_mask_to_bytes` 再兜一层 |

阈值取 alpha ≥ 190（约 75% 覆盖），主体笔画实心、边缘留一档毛边。

效果：自造版 avg=0.25 / max=0.35，与原厂 0.24 / 0.32 基本持平。

### 2.3 启动时体检并自动替换

`check_font_file()` 抽查 20 个常用汉字的墨迹率：

- `avg > 0.32` 或 `max > 0.45` → 判定**笔画粘连**，重新准备；
- 常用汉字字模缺失 → 判定**不可用**。

老板那份糊字库，下次启动会自动换成原厂版：

```
[font] 现有字库 gb16.uc2 质量不合格（笔画粘连（墨迹率 avg=0.37 max=0.59，阈值 0.32/0.45）），重新准备
[font] 已采用原厂字库 gb16.uc2 -> gb16.uc2（2097152 字节）
```

**只按文件大小判断是不行的** —— 糊字库 1310720 字节看着完全正常，
必须抽查内容。

### 2.4 提到全局启动流程

原先字库只在 `--retro-wap on`（准备 QQ 环境）时才生成。现在
`cli.py` 启动时**无条件**准备一次 —— 任何 MRP 应用都可能读
`system/gb16.uc2`，不该只有 QQ 能用。

## 三、问题二：支付成功后野指针崩溃

### 3.1 现象

调用支付插件，支付成功后崩溃：

```
[vm] 执行异常 Invalid memory write (UC_ERR_WRITE_UNMAPPED) @ PC=0x302644
[vm] 非法访问: @0x46C4891D(4B) PC=0x302644
[vm] timer 异常: Invalid memory write (UC_ERR_WRITE_UNMAPPED)
```

`0x46C4891D` 明显是**未初始化数据**被当指针用。

### 3.2 宿主接口语义与真机不一致

对照 SKYENGINE 手册（`docs/api/mr_plat-*.md`），发现两处语义错：

**① `mr_getUserInfo` 字段错位**

官方 `mr_userinfo`（`mrporting.h` / `dl_mrporting.h` 两处一致）：

```c
typedef struct {
   uint8 IMEI[16];        // +0
   uint8 IMSI[16];        // +16
   char  manufactory[8];  // +32
   char  type[8];         // +40
   uint32 ver;            // +48
   uint8 spare[12];       // +52
} mr_userinfo;
```

我们的实现把 IMEI 写在 +16、厂商名写在 +0 —— **整体错位**，而且
`type` / `ver` **根本没填**，应用读到的是未初始化内存。
官方 `mythroad.c:5375` 拿到 info 后直接 `setstrfield(L, "hstype", info.type)`
把它当 C 字符串用，遇到未初始化内存就会解引用野指针。

**② 未实现的 `mr_plat` code 返回了 MR_SUCCESS**

手册对绝大多数 code 都写明「未实现返回 MR_IGNORE」。我们返回
MR_SUCCESS(0)，等于告诉应用「成功且结果为 0」—— 应用会把 0 当成
真实数据继续用。

### 3.3 修复

| 位置 | 修复前 | 修复后 |
|---|---|---|
| `mr_getUserInfo` | 字段错位、`type`/`ver` 未填 | 严格按官方布局填充，整块先清零 |
| `mr_plat` 未知 code | 返回 `MR_SUCCESS`(0) | 返回 `MR_IGNORE`(1) |
| `mr_platEx` 未知 code | 返回 `MR_SUCCESS`，**output 缓冲区不写** | 返回 `MR_IGNORE`，并把 `*output` 置 NULL、`*output_len` 置 0 |

`platEx` 那条尤其关键：`output` 是 `uint8**`，应用很可能先读
`*output` 再判断返回值。我们从没写过它，应用读到的就是栈上垃圾。

顺带补了几个有明确手册语义的 code：`1100`（短信模块状态）、`1101`
（短信条数）、`1106`（短信中心）、`1205`/`1206`（触摸屏/中文）、
`1211`（随机数）、`1214`、`1011`。

## 四、回归

新增 `tests/font_probe.py`（32 项），守住：

1. 自造字库的**字形不粘连**（逐字墨迹率）；
2. 字模**位序正确**（严格 16×16、MSB-first、左右不翻转）；
3. `ensure_uc2` **优先原厂**、**自动替换糊字库**；
4. 端到端启动 QQ 时字库**必须可用**。

另外：

- `tests/rx_env.py` 补字库复制 —— 隔离测试环境以前不带字库，
  日志里一直有 `font load fail`；
- `tests/crash_probe.py` 同样补上 —— 缺字库时崩溃类型会从「写未映射」
  变成「读未映射」，断言对不上。

全套 20 个探针 **rc=0、0 失败**。

## 五、经验

1. **「界面文字糊」要先分清是谁画的**。位图清晰、点阵文字糊，就说明
   问题在点阵字库，不在宿主字体。换宿主字体（宋体/雅黑）是治标 ——
   MRP 应用的文字根本不走宿主字体。

2. **优先找现成的真机资源**。发行包里就有原厂点阵字，自己造一份更差的
   纯属画蛇添足。

3. **质量不能只看文件大小**。糊字库 1310720 字节看着完全正常，
   只有抽查内容（墨迹率）才能发现。

4. **缩放是点阵化的天敌**。真机点阵字是逐笔画出来的，任何缩放方案都会
   让笔画互相渗透。

5. **注意 pygame 的 alpha 语义**。`font.render(antialias=True)` 返回
   SRCALPHA surface，抗锯齿在 alpha 通道，读 RGB 会得到全白。

6. **宿主接口的「未实现」语义要当真**。返回「成功」比返回「不支持」
   危险得多 —— 应用会把垃圾数据当真实结果继续用。
