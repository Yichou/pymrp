# 12 · MTK 真机启动界面与游戏中心

> **状态**：本页描述 pymrp 宿主层新增功能（2026-11-10）。所有格式结论均为 A 级实测；
> 网络数据源行为按 2026-11-10 的 vmrp.github.io 仓库状态记录，站点改版后需重新核对。

## 1. 为什么分两层

真机的「待机桌面 / 九宫格菜单 / 应用列表」是**手机系统自己的界面**，
不是 MRP 应用；MRP 只是在系统拉起它之后接管 240×320 的屏幕。
所以这一层用 Python 直接画一张 240×320 的 Surface 交给 `PhoneUI` 贴进机壳，
与 MRP 的帧缓冲完全同尺寸、同坐标系：

```
┌───────────────────────────────────────────────┐
│ PhoneUI（机壳/键盘，skin.json，300×660）        │
│   ┌───────────────────────────────────────┐   │
│   │ 屏幕 240×320                          │   │
│   │   launcher 模式 → Launcher.surface()  │   │
│   │   mrp 模式      → app.gfx.surface()   │   │
│   └───────────────────────────────────────┘   │
└───────────────────────────────────────────────┘
```

鼠标点屏幕时 `PhoneUI.screen_pos()` 把窗口坐标换算成 240×320 坐标，
原样交给 `Launcher.handle_click()`；点机壳按键则由 `hit()` 拿到 key id
再翻译成键名。两种输入走同一套状态机。

## 2. 四个页面

| 页面 | 内容 | 进入方式 |
|---|---|---|
| `boot` | MTK 椭圆 logo、PymRP、进度条、按任意键跳过（1.5s） | 默认开机 |
| `home` | 待机桌面：信号/中国移动/时钟/日期/电池、渐变山丘壁纸、游戏中心快捷框 | 开机结束 / 游戏里按挂机键 / 菜单按返回 |
| `menu` | 3×3 九宫格，橙色高亮选中框 | 左软键「菜单」或点桌面空白处 |
| `gamecenter` | ① 在线列表 / ② 本地列表，5 行一页、图标+标题+厂商+大小、进度/已下载标记 | 点游戏中心图标 / 右软键 |

九宫格里「游戏中心」进 `gamecenter`，「应用列表」直接拉起真实 MRP 启动器
`dsm_gm.mrp`，其余格子明确提示「功能开发中」（不做假按钮）。

## 3. 列表数据从哪来

### 3.1 在线列表：一次拉索引，不逐个下包

数据源是老板指定的 `https://github.com/vmrp/vmrp.github.io/tree/master/public`：

| 路径 | 内容 | 大小 |
|---|---|---|
| `public/data.txt` | **NDJSON**，664 行，站点自己用 `mrp.readMrpInfo()` 从每个包里读出的元数据 | 362 KB |
| `public/mrps/` | 664 个 `.mrp` 文件本体 | 各不相同 |
| `public/js/` | 站点前端（Vue + NeDB），`readMrpInfo` 的字段来源可在此核对 | — |

一行样例（字段直接可用，不用再解包）：

```json
{"FileStart":6466,"MrpTotalLen":421185,"MRPHeaderSize":240,
 "FileName":"gwuytq.mrp","DisplayName":"激情美女台球HD","AuthStr":"9412ef5f6",
 "Appid":311088,"Version":1011,"Flag":7,"BuilderVersion":10002,
 "Crc32":1010058986,"Vendor":"南京颂歌","Desc":"与美女郎共，展现台球高手风采",
 "file":"311088_240320_gwuytq.mrp"}
```

**关键取舍**：664 个包合计上百 MB，逐个下载再读头是不现实的。
`data.txt` 就是站点已经做好的那份「从 MRP 里读出来的标题/开发商/描述」，
拉 362 KB 一次搞定；再用一次 GitHub contents API 补准文件大小。
只有用户真的点了某个应用，才下载那一个包。

### 3.2 本地列表：读每个包的前 240 字节

`mrp_emu/catalog.py::read_mrp_header()` 按 [03 号文档](03-MRP包格式规范.md)
解固定头：0x1C 标题、0x58 厂商、0x80 描述、0x44 appid、0x48 version。
字段长度与官方《mythroad 工程文件（mpr 文件）编写指南》的上限一一对应
（appname 23 / vendor 39 / description 63 / filename 11 ASCII）。
扫描 `workdir` 下全部 `*.mrp`，跳过 `cache/`，生成 `local_index.json`。

### 3.3 JSON 缓存

```
<workdir>/cache/online_index.json    664 条在线索引 + fetched_at + source
<workdir>/cache/local_index.json     本地扫描结果 + generated_at + root
<workdir>/mythroad/<下载的应用>.mrp  点过的在线应用落到运行环境
```

- 首次进入游戏中心，`Catalog.start_refresh()` **在后台线程**拉一次，UI 不卡；
- 之后启动先读 JSON，7 天内（`--cache-days`）不发网络请求；
- 过期才静默刷新；失败保留旧缓存并提示；`--refresh` 强制重拉；
- 「已下载」状态**以磁盘为准**，不信缓存文件里的布尔值（曾踩过一次坑）；
- 下载的 MRP 落到 `workdir/mythroad/`，正是 DSM 层默认查找目录，因此
  下载过的在线应用会自动出现在本地列表里。

## 4. 点一下就玩：完整链路

```
点击列表行
  ├─ 本地项 / 已下载的在线项 ──────────────┐
  └─ 未下载的在线项 → 后台下载到 mythroad/ │
                       → 下载完成事件 ─────┤
                                          ▼
                        cli.launch_path()（重建干净的 VM）
                          ├─ Vm() / App() / install_tables()
                          ├─ load_code(cfunction.ext) → ext_init() → dsm_init()
                          ├─ probe_entry_ext() 读条目表决定入口（通常 start.mr）
                          └─ start_dsm(filename, ext) == 0 → mode = "mrp"
                                          │
                          挂机键 END → back_to_home() → mode = "launcher"
```

三个容易踩坑的点，都已实测：

1. **入口是 `start.mr` 不是 `cfunction.ext`**。给普通应用传 `cfunction.ext`
   会报 `exit de is nil! / init failed` 并返回 -1；15 个本地样本 +
   在线抽样包内都有 `start.mr`。详见 [03 号文档 §9](03-MRP包格式规范.md)。
2. **每次启动重建 VM**，避免上一个应用的全局状态残留。同进程连续启动
   5 个不同 MRP 全部返回 0，无段错误；音频引擎跨会话复用（整机只有一个喇叭）。
3. **挂机键回桌面**，不发 `MR_KEY_RELEASE` 给已经停掉的 VM。

## 5. 操作

| 操作 | 键盘 | 鼠标 |
|---|---|---|
| 待机 → 主菜单 / 游戏中心 | 左软键(F1) / 右软键(F2) / 方向键+确定 | 点桌面、点底部软键、点游戏中心框 |
| 九宫格选择 | 方向键、确定 | 直接点图标 |
| 在线 ↔ 本地 | ← / → | 点 Tab |
| 列表翻页 | ↑ / ↓，`9` 上翻 5 条、`3` 下翻 5 条 | 点行 = 直接打开 |
| 搜索 | `*` 或 `#` 进入，输入关键字（标题/文件名/厂商/描述），`CLEAR` 退格 | 点标题栏右侧 |
| 打开应用 | 确定 / 左软键 | 点击列表行 |
| 返回 / 退出应用 | 右软键、`END`(Esc)；游戏里按挂机键直接回桌面 | 点机壳挂机键 |

在线项未下载时显示下载百分比与进度条，下完自动启动，不用再点一次。

## 6. 命令行

```bash
python run.py                                  # 开机动画 → 待机桌面
python run.py --boot gamecenter                 # 直接进游戏中心
python run.py --boot home|menu                  # 调试某一页
python run.py --refresh                         # 强制刷新在线索引
python run.py --cache-days 30                   # 缓存有效期改成 30 天
python run.py --proxy http://127.0.0.1:7890     # 显式代理
python run.py game.mrp                          # 跳过桌面，直接跑 MRP（旧行为）
python -m mrp_emu.catalog scan --workdir runtime
python -m mrp_emu.catalog head runtime/mythroad/box.mrp
python -m mrp_emu.catalog get 2048.mrp --workdir runtime
```

网络走 `urllib.request.getproxies()`（系统代理 / `http_proxy` 环境变量 /
`PYMRP_PROXY`）。直连失败时会自动探测本机 `7890 / 7897 / 10809 / 1080`
这几个常见代理端口并记住结果 —— 老板机器上开着的 Clash 走 7890，无需额外配置。

## 8. 已知限制

- 在线索引是**第三方仓库的静态快照**（664 条，2021 年前后），站点改版或
  文件删除时会 404；下载失败只提示，不影响本地列表。
- `data.txt` 里少数条目的 `Appid`/`Version` 是老 builder 的随机填充值，
  列表只把它们当图标配色种子，不作展示依据。
- 部分 MRP 依赖包外资源（字库、插件、存档目录），缺文件时 DSM 会打
  `[fs] 打开失败` 日志，多数应用仍能进主菜单。
- 搜索对中文依赖输入法的 `TEXTINPUT` 事件；英文/拼音缩写（在线文件名多为
  拼音缩写）在所有平台都可用。
- 这是宿主 UI，不是 MRP 应用：它不会出现在 `dsm_gm.mrp` 的应用列表里，
  也不占用任何 MRP 内存。
