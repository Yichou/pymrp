# 古董 QQ 复活：协议逆向与本地服务端

> 对象：`391032_240320_atxqq.mrp`（爱Q手机QQ，MTK WAP 版）
> 与 `QQDSM2007.mrp`（QQ 2007，原生二进制协议版）
> 结论：**服务端已彻底消失，只能自建**；本仓库已实现可运行的本地替代。

---

## 一、服务器现状：全死，没有第三方替代

| 端点 | 归属 | 实测状态（2026-11-11） |
|---|---|---|
| `info.3g.qq.com/g/s?aid=index` | 腾讯 WAP 门户 | **302** 到 `https://` 后失效 |
| `3g.qq.com` | 腾讯 WAP 门户 | **502** |
| `conf.3g.qq.com/newConf/n` | 腾讯服务器列表 | **502** |
| `activeqq.3g.qq.com/activeQQ/gkey2sid.jsp` | 腾讯密钥换 SID | **502** |
| `wap.skmeg.com` / `rop.skymobiapp.com` | 斯凯代理 | 复刻机 `159.75.119.124` 只代理自己那几个域名，QQ 相关一律 **502** |
| `www.sky-mobi.com` | 斯凯 QQ 网关 | 已停运 |

历史脉络：腾讯 2007 年推出 **3GQQ**（WAP 版 QQ，浏览器直接聊天）；2010 年
推出手机 QQ 客户端（就是本包）；2014 年前后随着 3G/2G 退网与智能机普及，
腾讯关闭了移动 QQ 的服务端；斯凯当年做的是**代收费代理**
（`Q-UA: SKYQQ10_GA/...`），其服务器也早已停运。

**没有任何可用的第三方替代**。要复活只能自建服务端。

## 二、两个包的架构

### 2.1 `391032_240320_atxqq.mrp`（2010，WAP 架构）

包内 43 个条目，含 **完整的 WAP 浏览器引擎**：

```
start.mr            1380    入口（loader）
mrc_loader.ext       211/319  加载器
cfunction.ext     222656    WAP 引擎（gzip，解压后 340140 字节）
mtt_start.wml       1988    门户首页模板（gzip）
mtt_config.wml       551    设置页模板
error1.wml/error2.wml       错误页模板
icon_*.gif / image_*.bin    图标与图片资源
```

**关键结论：这个 MRP 自己就是 WAP 浏览器**，服务器只负责吐 WML 页面，
渲染由 MRP 内部完成 —— 所以我们**不需要写 WML 渲染器**，只要供页面。

聊天入口是伪协议 `mtt:qq`（浏览器把它交给内置的 QQ 插件）。

启动时它要读一堆**真机预置的私有资源**（详见 §四）。

### 2.2 `QQDSM2007.mrp`（2007，原生二进制协议）

条目都是 gzip 压缩的 `.mr` 模块，**协议完全可读**（解压后是字符串表）：

| 模块 | 内容 |
|---|---|
| `protocol.mr` | 协议编解码：URL 格式串、命令集 |
| `network.mr` | HTTP 客户端：建连、收发、超时重发 |
| `startqq.mr` | 启动流程 + **内置测试账号表**（用户名 + 16 位 hex 密码哈希） |
| `common.mr` | 公共库：服务器地址读取、`%0.2x` 哈希格式化 |
| `validate.mr` | 登录校验 |

## 三、协议逆向成果

### 3.1 斯凯 QQ 代理协议（HTTP GET，明文参数）

`protocol.mr` 里的请求格式串：

```
VER=1.3&CON=1&CMD=LOGIN&SEQ=<n>&UIN=<qq>&PS=<pwd>&M5=1&LG=<n>&LT=<n>&LC=<n>
```

命令集（`network.mr` / `protocol.mr` 字符串表）：

| 命令 | 含义 | 关键参数 |
|---|---|---|
| `LOGIN` | 登录 | `&UIN=&PS=&M5=1&LG=&LT=&LC=` |
| `LOGOUT` | 登出 | `&UIN=&SID=` |
| `HELLO` | 心跳 | `&UIN=&SID=` |
| `QUERY_STAT` | 查好友状态 | `&TN=&UN=` |
| `LIST` | 取好友列表 | `&TN=&UN=` |
| `CLTMSG` | 发消息 | — |
| `GETINFO` | 取资料 | — |
| `FINGER` | 找用户 | `&AG=&SX=&PV=` |
| `ADDTOLIST` | 加好友 | `&UN=` |
| `ACK_ADDTOLIST` | 应答 | `&UN=&CD=&RS=` |
| `DELFROMLIST` | 删好友 | `&UN=` |
| `VERIFYCODE` | 验证码 | — |

服务器响应头（`network.mr`）：

```
x-sp-result: <code>
content-length: <len>
```

响应体是 `RES=<...>` 之类的键值串（`protocol.mr` 里出现 `RES`）。

`network.mr` 还揭示了客户端的 HTTP 栈：`httpCreate` → `connect` →
`sendbuf` → `httpRecCb`（解析 `x-sp-result` / `content-length`）→
`analizeQQPack`。

### 3.2 服务器发现流程（2010 版，WML 架构）

`cfunction.ext` @0x4C328 附近的字符串串起了整条链：

```
http://%s/                          <- 用配置里的主机拼 URL 前缀
%d                                   <- 端口
QServer.cof                          <- 服务器列表配置文件
socket://                            <- 另一条直连通道
auto.conf                            <- 配置里的子文件名
%u                                   <- QQ 号
E1D84CC825147ECD                     <- 配置加解密密钥（16 位 hex）
http://conf.3g.qq.com/newConf/n      <- 在线拉取服务器列表
result=0&                            <- 拉取成功的响应前缀
http://activeqq.3g.qq.com/activeQQ/gkey2sid.jsp?s_ua=j2me&g_key=%s
                                     <- 密钥换 SID（登录前置）
```

流程：读 `QServer.cof` → 没有就去 `conf.3g.qq.com/newConf/n` 拉
（响应 `result=0&<服务器1>&<服务器2>...`）→ 落盘 → 用 `g_key` 换 SID →
走 `VER=1.3&CON=1&CMD=...` 协议。

## 四、私有文件格式（已逆出的部分）

### 4.1 `QServer.cof`（2010 版，**二进制**）

动态分析（在 `fs.read` 上打点）得到的读取模式：

* 先读 **1 字节**（版本号）
* 再反复读 **4 字节**，读到 0 字节表示结束

```
u8  版本
u32 服务器编号   × N（0 表示列表结束）
```

### 4.2 `qqdsm/settings`（2007 版，**文本**）

整个文件一次读完，按 `key=value` 逐行。键名来自 `common.mr`：
`www.sky-mobi.com` / `port` / `_ip` / `_port`。

### 4.3 `profile.db`（账号库）

`PROF` magic（4 字节）+ `0x80` 偏移处的数据块。完整格式未逆出
（斯凯自有的 DB 格式），本地只写最小 magic 头让应用走「首次运行」分支。

### 4.4 `system/gb16.uc2`（16 点阵字库）

格式来自 mrpoid 官方 `font/font_sky16_2.c`：

```c
ft_seek(font_sky16_f, id * 32, 0);      /* 偏移 = 字符 id * 32 */
ft_read(font_sky16_f, font_sky16_bitbuf, 32);
/* 每个字模 16x16 = 256 bit = 32 字节，1bpp，高位在前 */
int getfontpix(char *buf, int n) {
    buf += n / 8;
    return (128 >> (n % 8)) & *buf;     /* 高位在前 */
}
```

**没有偏移表**，直接按 `id * 32` 线性索引。`id` 的含义有歧义：

| 假设 | 实测 |
|---|---|
| Unicode 码位（`0x4E2D` = 「中」） | ✅ **本仓库的 ext 用这个** |
| GB2312 下标（`(hi-0xA1)*94+(lo-0xA1)`） | ❌ 字形全错乱 |

两个布局各生成一份实测对比，`unicode-first` 正确、`gb-first` 错乱，
所以默认 `unicode-first`。

## 五、模拟器侧的三处修复

### 5.1 `mr_platEx(1207)` = `MR_UCS2GB`（大端 UCS-2 → GBK）

官方语义（mrpoid `dsm.c:1788`）：

* `input` 是**大端** UCS-2 字符串；
* `output` 是 `uint8**`，指向**调用者提供**的输出缓冲区，
  转换结果写进该缓冲区（不重新分配）；
* `output_len` 是 `int32*`，官方注释写的是「output 缓冲区的长度，
  单位字节数」——即**容量**，不是结果长度。

之前我们**没实现这个 code**，只回了个 `MR_SUCCESS` 而不写输出，
应用拿到空缓冲区，于是去开 `mythroad/file:/E:/QQ2010/...` 这种鬼路径。

### 5.2 文件系统的盘符 / URI 映射

真机上 `E:` 盘就是应用数据根，`file:/` 是 WML 里的 URI 方案。
`fs.py::resolve()` 现在把下面四种写法统一落到 `mythroad/` 下：

| MRP 里的写法 | 落到 |
|---|---|
| `mythroad/QQ2010/res/x.gif` | `mythroad/QQ2010/res/x.gif` |
| `E:/QQ2010/res/x.gif` | `mythroad/QQ2010/res/x.gif` |
| `file:/E:/QQ2010/res/x.gif` | `mythroad/QQ2010/res/x.gif` |
| `mythroad/file:/E:/QQ2010/res/x.gif` | `mythroad/QQ2010/res/x.gif` |

### 5.3 MRP 包内资源释放（真机行为）

MTK 应用把图标/WML 打包在 `.mrp` 里，启动时释放到自己的目录
（`E:\QQ2010\res\`）。我们以前只把 .mrp 当「可执行文件」跑，
于是应用打开 `mythroad/QQ2010/res/icon_*.gif` 全部失败，页面空白。

新增 `mrp_emu/release.py`：

* `read_mrp_entries()` —— 完整条目表解析（自动剔除越界的包尾标记）；
* `read_mrp_entry_data()` —— 取条目内容，gzip 自动解压；
* `detect_app_dirs()` —— 从包内资源里反推应用自己的目录名
  （扫 `E:\xxx\` 绝对路径前缀取频次最高者）
  ——实测 `391032_240320_atxqq.mrp` → `["QQ2010", "QQ2010Download",
  "QQBrowser"]`，`dsm_gm.mrp` → `["downdata"]`；
* `release_mrp_resources()` —— 释放到 `<workdir>/mythroad/<app_dir>/`。

CLI 启动 MRP 前自动调用。

## 六、本地复古服务端

### 6.1 `mrp_emu/retrowap.py` —— WAP 服务器

线程化的 HTTP 服务器，按路径返回 WML 页面：

| 路径 | 内容 |
|---|---|
| `/g/s?aid=index` | 门户首页（结构照抄包内 `mtt_start.wml`） |
| `/g/channels/*` | 分类页（新闻/体育/社区…） |
| `/mtt/qq` | QQ 登录页（`mtt:qq` 伪协议的落地页） |
| `/qq/login` | 登录结果页 |
| `/qq/chat` | 聊天页 |

响应 `Content-Type: text/vnd.wap.wml; charset=utf-8`，
并记录全部请求（供抓包分析与回归断言）。

### 6.2 域名覆写

`retrowap.dns_map_for()` 把 12 个腾讯 3G 域名全部指向本机：

```
info.3g.qq.com / 3g.qq.com / misc.3g.qq.com / gp.3g.qq.com /
res.3g.qq.com / jwt.3g.qq.com / music33.3g.qq.com / ebook.3g.qq.com /
wap.3g.qq.com / wap.3g.cn / z.qq.com / w.mail.qq.com
```

配合模拟器已有的 `--dns-map` + 内置 WAP 代理（接管 CMWAP 的
`10.0.0.172`），请求就被引到本地。

### 6.3 `mrp_emu/qqenv.py` —— 运行环境准备

一次生成古董 QQ 需要的全部真机预置文件：

```
mythroad/QQ2010/QServer.cof     二进制服务器列表
mythroad/QQ2010/profile.db      PROF magic 账号库
mythroad/qqdsm/settings         文本服务器地址
mythroad/qqdsm/info             空账号信息
mythroad/system/gb16.uc2        16 点阵字库
```

### 6.4 `mrp_emu/fontgen.py` —— 本地造点阵字库

用系统字体（宋体优先）渲染成 MTK 的 16×16 1bpp 点阵：

* 字号必须够大：**64px 渲染再缩到 16px**。16px 字号下宋体汉字只有
  ~10px 宽，细笔画在缩放时被阈值吃掉（「网」整个消失、「输」只剩
  两个方块）。
* 用**不透明黑底白字**画布，不要 `SRCALPHA`：半透明画布经
  `smoothscale` 后 alpha 被平均，中心 alpha 也只剩 ~111，阈值很难定。
* **加粗**一档：宋体的细横/细竖缩到 16px 后只剩 1 个点，看着像虚线，
  真机字库是粗宋体/仿宋。
* 缩放后**不要再做二次裁剪放大** —— 那一步会把字形撑成实心方块。
* 性能：逐像素 `get_at` 是瓶颈（40000 字 × 256 像素 = 1000 万次
  Python 调用），改用 numpy 批量转换后从 9 秒降到 ~4 秒。

生成结果：1.3 MB（Unicode 区覆盖 0x0000-0xA000），一次生成后缓存复用。

## 七、怎么跑

```bash
# 2010 版（WAP 架构）：自动起本地服务端 + 备好环境 + 生成字库
python run.py "runtime/mythroad/391032_240320_atxqq.mrp" \
    --workdir runtime --retro-wap on

# 2007 版（原生二进制协议）
python run.py "runtime/mythroad/QQDSM2007.mrp" --workdir runtime --retro-wap on
```

首次会生成字库（约 4 秒），之后走缓存。

## 八、当前边界

| 项 | 状态 |
|---|---|
| WAP 门户首页（图标 + 中文 + 输入框 + 菜单） | ✅ 完整渲染 |
| 2007 版 QQ 登录界面 | ✅ 渲染正常（企鹅 + 账号/密码框 + 软键） |
| 服务器列表 / 账号库格式 | ✅ 已逆出并自动生成 |
| 点阵字库 | ✅ 本地生成，Unicode 索引 |
| QQ 聊天协议（`VER=1.3&CON=1&CMD=...`） | ⚠️ 格式已完全逆出，**服务端未实现** |
| 真实 QQ 服务器 | ❌ 全部停运，无第三方替代 |

聊天要真跑起来，还需要：

1. 实现 `retrowap` 的 QQ 协议端点（`LOGIN`/`LIST`/`CLTMSG`…），
   按 §三 的格式收发；
2. 弄清 `profile.db` 的完整格式（当前只写 magic 头，走「首次运行」分支）；
3. 账号体系 —— 老协议的 `&PS=` 是 16 位 hex 哈希（`startqq.mr` 里有一张
   测试账号表可参考：`desheng`/`0CB53BBB8F561019` 这样的对应关系）；
4. 「超级 QQ」/计费相关（`%w %d.%02dk`、`%w %d/%d` 这些格式串说明
   有流量计费逻辑）需要另找当年的计费协议。

前 3 项在本地都能做，只是工作量不小；第 4 项依赖已消失的运营商计费接口，
建议用本地服务端时**绕过计费**（直接给固定额度或不限流量）。
