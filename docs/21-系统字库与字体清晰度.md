# 系统字库修复：中文为什么糊成一坨

> 现象：老板截图反馈「系统字体糊掉了，改用宋体或者微软雅黑」。
> 结论：**不是模拟器 UI 的字体问题**，是 DSM 层**系统点阵字库**的质量问题。
> 已修复：优先复用原厂字库 + 修正自造算法 + 启动时自动体检。

---

## 一、现象定位

截图是 QQ 2007（`QQDSM2007.mrp`）的登录界面。放大后能看清三件事：

| 元素 | 清晰度 |
|---|---|
| QQ 企鹅 logo、QQ2007 logo | **清晰**（包内位图资源） |
| 输入框、勾选框、按钮 | **清晰**（应用自己画的位图） |
| 「帐号」「密码」「记住密码」「隐身登录」 | **糊成一坨**（点阵字） |

结论：糊的只有**用点阵字库渲染的中文**。位图资源没问题，模拟器的
Python 侧 UI 字体（`ui/launcher.py` 用微软雅黑）也不是瓶颈。

---

## 二、根因

### 2.1 应用走的是 DSM 系统字库

抓 QQ 2007 的启动日志：

```
[fs] open 'mythroad/system/gb16.uc2' mode=0x0 -> 1
[arm] [INFO]mr_open(mythroad/system/gb16.uc2,0) fd is: 1
[arm] [INFO]font load suc fd=1
```

应用启动第一件事就是打开 **`mythroad/system/gb16.uc2`**，然后按
`seek(id * 32)` 取 16×16 的 **1bpp** 字模，在 ARM 侧自己画中文。
**这条路径完全在虚拟机里**，宿主的 Python 字体完全不参与。

### 2.2 我们自造的字库笔画粘连

早期 `fontgen.py` 的做法是：

```
64px 粗体渲染 -> smoothscale 缩到 16x16 -> 灰度阈值化
```

缩放会让**相邻笔画互相渗透**，缩完再阈值化，笔画之间就**粘死**了：

- 墨迹率（黑像素占比）实测：
  - 原厂 `fonts/gb16.uc2`：**avg 0.236 / max 0.316**
  - 早期自造版：**avg 0.367 / max 0.594** ← 明显过粗
- 视觉对比见 `out/font_compare2.png` 第一行 vs 第二行。

### 2.3 发行包里本来就有原厂字库

`runtime/mythroad/fonts/` 里躺着：

| 文件 | 大小 | 字模数 |
|---|---|---|
| `gb16.uc2` | 2 MB | 65536 |
| `sky16.uc2` | 2 MB | 65536 |
| `gb12v2.uc2` | 1.1 MB | 12 点阵 |

这些是**当年烧进固件的手工点阵字**，清晰度远高于任何系统字体缩放
结果，而且**索引方式一致**（Unicode 码位，实测 `seek(ord(ch) * 32)`
取出的就是正确的字）。

**我们此前却在自己造一份更差的**，覆盖了 `system/gb16.uc2`。

---

## 三、修复

### 3.1 优先复用原厂字库（`fontgen.ensure_uc2`）

三级策略：

1. 目标已存在 **且质量合格** → 直接用；
2. 发行包里有原厂字库 → **复制过来**（最清晰，且与真机一致）；
3. 都没有 → 用系统字体（宋体 → 微软雅黑）现场生成，作为兜底。

### 3.2 修正自造算法（`fontgen._glyph_mask`）

三个坑，逐个踩过：

| 坑 | 现象 | 解法 |
|---|---|---|
| 64px 缩放 | 笔画粘连成黑块 | **16px 直接渲染**，不缩放 |
| 读 RGB 通道 | 每个字都是实心方块（墨迹率 1.0） | `render()` 返回 **SRCALPHA** surface，抗锯齿在 **alpha 通道**，RGB 全是 255 |
| 二次裁剪 | 行宽变成 14/15，位序错乱成乱码笔画 | `_fit_mask` 保证输出**严格 16×16**；`_mask_to_bytes` 再兜一层 |

阈值取 alpha ≥ 190（约 75% 覆盖率），主体笔画实心、边缘留一档毛边。

### 3.3 启动时自动体检 + 替换

`check_font_file()` 抽查 20 个常用汉字的墨迹率：

- `avg > 0.32` 或 `max > 0.45` → 判定**笔画粘连**，重新准备；
- 常用汉字字模缺失 → 判定**不可用**。

老板那份糊字库在下次启动时会被自动识别并换成原厂版：

```
[font] 现有字库 gb16.uc2 质量不合格（笔画粘连（墨迹率 avg=0.37 max=0.59，阈值 0.32/0.45）），重新准备
[font] 已采用原厂字库 gb16.uc2 -> gb16.uc2（2097152 字节）
```

### 3.4 提到全局启动流程

原先字库只在 `--retro-wap on`（准备 QQ 环境）时才生成。现在
`cli.py` 启动时**无条件**准备一次——任何 MRP 应用都可能读
`system/gb16.uc2`，不该只有 QQ 能用。

## 四、效果

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 原厂字库 | — | 中文清晰可辨（墨迹率 avg 0.24） |
| 自造兜底（无原厂） | 笔画粘连 | 中文清晰可辨（墨迹率 avg 0.25） |
| 生成耗时 | ~10 s | **2.2 s** |

实测对比图：

- `out/font_compare2.png` —— 原厂 vs 旧自造 vs 新自造
- `out/qq_fixed_z.png` —— 修复后的 QQ 2007 登录界面
- `out/qq_selfgen_z.png` —— 无原厂字库时的自造兜底效果

> 顺带发现：换上正确的字库后，界面文案也从「帐号/密码」变成了
> **「QQ号码/QQ密码」**——旧字库缺字导致应用取到了错误的备用串。

## 五、回归

新增 `tests/font_probe.py`（32 项），守住：

1. 自造字库的字形**不粘连**（逐字墨迹率）；
2. 字模**位序正确**（严格 16×16、MSB-first、左右不翻转）；
3. `ensure_uc2` **优先原厂**、**自动替换糊字库**；
4. 端到端启动 QQ 时字库**必须可用**（不出现 `font load fail`）。

`tests/rx_env.py` 也补上了字库复制——隔离测试环境以前不带字库，
日志里一直有 `font load fail`，现在归零。

全套 20 个探针全部 rc=0、0 失败。

## 六、经验

1. **「界面文字糊」要先分清是谁画的**。本例中位图清晰、点阵文字糊，
   说明问题在点阵字库，不在宿主字体。换宿主字体（宋体/雅黑）是
   治标——MRP 应用的文字根本不走宿主字体。

2. **优先找现成的真机资源**。发行包里就有原厂点阵字，
   自己造一份更差的纯属画蛇添足。

3. **质量不能只看文件大小**。糊字库 1310720 字节，看着完全正常；
   只有抽查内容（墨迹率）才能发现。

4. **缩放是点阵化的天敌**。真机点阵字是逐笔画出来的，
   任何缩放方案都会让笔画互相渗透。

5. **注意 pygame 的 alpha 语义**。`font.render(antialias=True)` 返回
   SRCALPHA surface，**抗锯齿在 alpha 通道**，读 RGB 会得到全白。
