# 13 · 网络模块与内存健壮性

> 2026-11-10 新增。两件事一起做：按 mrpoid `network.c` 补齐 MRP 网络协议栈；

## 2. 接口契约：两张表，参数不一样

这是最容易写错的地方。`cfunction.ext` 是 vmrp 编译出来的 **ARM 移植层**，
它自己实现了 MRP 应用看到的 `mrc_*` 网络函数（ext 里有
`[INFO]mr_initNetwork(mod:%s)` 等日志字符串为证），再回调宿主
`dsm_require_funcs` 里的底层函数。所以真正要补的是后者。

`vmrp/dl_dsm.h`（**A/C**）：

```c
typedef int32 (*NETWORK_CB)(int32 result, void *userData);

int32 (*getHostByName)(const char *ptr, NETWORK_CB cb, void *userData);   // 0x6C
int32 (*initNetwork)(NETWORK_CB cb, const char *mode, void *userData);    // 0x70
int32 (*mr_closeNetwork)();                                              // 0x74
int32 (*mr_socket)(int32 type, int32 protocol);                           // 0x78
int32 (*mr_connect)(int32 s, int32 ip, uint16 port, int32 type);          // 0x7C
int32 (*mr_getSocketState)(int32 s);                                      // 0x80
int32 (*mr_closeSocket)(int32 s);                                         // 0x84
int32 (*mr_recv)(int32 s, char *buf, int len);                            // 0x88
int32 (*mr_send)(int32 s, const char *buf, int len);                      // 0x8C
int32 (*mr_recvfrom)(int32 s, char *buf, int len, int32 *ip, uint16 *port);// 0x90
int32 (*mr_sendto)(int32 s, const char *buf, int len, int32 ip, uint16 port);// 0x94
```

而 MRP 标准 API `mr/mrporting.h`（**B**）里同名函数**少一个 userData**：

```c
int32 mr_initNetwork(MR_INIT_NETWORK_CB cb, const char *mode);
int32 mr_getHostByName(const char *name, MR_GET_HOST_CB cb);
```

pymrp 因此把 `dsmfuncs.py` 的 `initNetwork` / `getHostByName` 别名单独指向
`dsm_initNetwork` / `dsm_getHostByName`（3 参数版），`mr_table` 用 2 参数版。
**别把两个别名合并**，否则 `userData` 会读到 R2 的随机残留值并传回回调。

`mr_recvfrom` / `mr_sendto` 的第 5 个参数在栈上（`ctx.arg(4)` 读 `[SP]`），
与 `vmrp/dl_bridge.c` 的 `getArg(uc, 4)` 一致（**C**）。

### 枚举值（`mr/mrporting.h`，**B**）

| 常量 | 值 |
|---|---|
| `MR_SOCK_STREAM` / `MR_SOCK_DGRAM` | 0 / 1 |
| `MR_IPPROTO_TCP` / `MR_IPPROTO_UDP` | 0 / 1 |
| `MR_SOCKET_BLOCK` / `MR_SOCKET_NONBLOCK` | 0 / 1 |
| `MR_SUCCESS` / `MR_FAILED` / `MR_WAITING` | 0 / -1 / 2 |

## 3. IP 字节序（踩过就会记一辈子）

`mr_connect(s, ip, port, type)` 的 `ip` 是 `a<<24 | b<<16 | c<<8 | d`，
表示 `a.b.c.d`。mrpoid `network.c`：

```c
static char* ip2str(uint32 ip, char *out) {
    sprintf(out, "%d.%d.%d.%d", ip >> 24, (ip & 0xff0000) >> 16,
            (ip & 0xff00) >> 8, ip & 0xff);
}
saddr.sin_addr.s_addr = htonl(ip);
```

即 `0x0A0000AC` = `10.0.0.172`（cmwap 网关），`0x7F000001` = `127.0.0.1`。
`mr_getHostByName` 返回 `ntohl(ret)`，同样是这个格式（**C**）。
pymrp 用 `u32_to_ip()` / `ip_to_u32()` 做转换，`recvfrom` 写回的 `*ip`
也用同一格式。

## 4. socket 状态机

按 `dsm.h` 的 `DSM_SUPPROT_SOC_NUM = 10`（原文拼写如此，别"修正"）建 10 个槽，
`mr_socket()` 返回**槽位下标**而不是 fd：

```
CLOSE --socket()--> OPEN --connect()--> CONNECTING --select可写+SO_ERROR=0--> CONNECTED
  ^                                          |                                  |
  +---------------- closeSocket() -----------+------ 任一错误 --> ERR ---------+
```

- `readStat` / `writeStat` 独立控制，与 mrpoid 一致；UDP 创建即可读可写。
- 非阻塞 connect 返回 `MR_WAITING`，应用轮询 `mr_getSocketState()`；
  阻塞 connect 内部 `select` 等待（8s 超时）后返回 `MR_SUCCESS`/`MR_FAILED`。
- `mr_recv` 无数据返回 `0`（不是 `MR_FAILED`），`MR_FAILED` 只留给真错误——
  老 MRP 靠这两个值区分"等一下"和"断线了"。
- `mr_send` / `mr_recv` 直接读写**模拟内存指针**，不是宿主内存地址。

### cmwap 代理（2008 年移动梦网的坑）

MRP 里大量应用把请求发到 `10.0.0.172:80`，靠 `Host` 或 `X-Online-Host`
头告诉 WAP 网关真实目标。mrpoid 的处理是：先假装连上，第一次 `mr_send`
时解析出真实主机，**重新 connect 这个 socket** 再发。pymrp 原样复刻
（`NetEngine._ensure_proxy_link`）。出站 HTTP 代理（Clash）则在此之上再做
一层 `CONNECT host:port`。

## 5. 异步回调必须手动切 r9

`NETWORK_CB` 是 ARM 侧函数指针，宿主不能在自己线程里直接调。vmrp 的
`bridge_dsm_network_cb()`（**C**）说明得很清楚：

```c
uc_reg_read(uc, UC_ARM_REG_R9, &r9);
uc_reg_write(uc, UC_ARM_REG_R9, &mr_c_function_P->start_of_ER_RW);
// ... runCode(uc, addr, CODE_ADDRESS, false) ...
uc_reg_write(uc, UC_ARM_REG_R9, &r9);   // 恢复
```

因为这条路径不经过 `mr_extHelper`，ARM 侧没机会自己设 r9（SB）。
pymrp 的 `Vm.call_arm()` 就是干这个的（见 `docs/02` 与 `vm.py` 注释）。

**另一个约束**：不能在 Unicorn 的 `emu_start()` 内部重入。所以
`NetEngine` 把回调排进队列，主循环每帧调一次 `app.net.poll()` 执行。
`initNetwork` 同时返回 `MR_SUCCESS` 并排一个成功回调 —— MRP 侧
`base_open()` 用返回值设 `socket.state`，`mr_initNetworkCB()` 再设一次，
两者都是 `MRSOCK_CONNECTED`，重复无害，但兼容了按异步方式写的 ext（**C**）。
`mr_getHostByName` 同理：同步返回 IP（MRP 侧 `_mr_getHost` 直接把返回值
写进 `socket.ip`）并额外排一个回调。

## 6. RX 管理器崩溃复盘

### 现象

```
[arm] [INFO]mr_platEx code=1204 in=... inlen=1 out=... outlen=...
[arm] [INFO]dsmSwitchPath 'C', 1, 002D81C4, 002D81C0
[arm] [WARN]SetDsmWorkPath():'./'
[vm] 执行异常 Invalid memory read (UC_ERR_READ_UNMAPPED) @ PC=0x8EF1C
  ... key_event -> event -> mr_event -> ext_helper -> run_code ...
```

### 定位（**A**，本地复现 + capstone 反汇编）

用 90 步真实按键序列复现成功，dump 寄存器：

```
R0=0x00000000  R1=0xFFFFFFFF  SP=0x002D8120  LR=0x0008F084  PC=0x0008EF1C
```

`0x8EF1C` 处是 ext 内 `my_vsprintf` 的 `strnlen`：

```asm
0008EF18  add   r0, r0, #1
0008EF1C  ldrb  r2, [r0]        ; <<<< 崩在这里，r0 == 0
0008EF20  cmp   r2, #0
0008EF2C  bne   #0x8ef18        ; 没遇到 NUL 就一直读
```

即：**格式化函数拿了一个 NULL `%s` 参数**。

### 完整根因链

1. RX 管理器（R_Xplore 文件浏览器）浏览到 C 盘根目录，路径变成 `./`；
2. 用户按方向键选中 `..`，ext 请求 `./..`；
3. 旧 `VirtualFs.resolve()` 遇到 `..` 越出 root，打印
   `[fs] 拒绝沙箱外路径: ./..` 并 **返回 None**；
4. 宿主目录/文件 API 因此给 ext 一个空结果，ext 内部把它当 `char*`，
   交给自己的 `SetDsmWorkPath()` 日志函数 `sprintf("[WARN]...'%s'", path)`；
5. `strnlen(NULL)` 读地址 0 —— **真 MTK 机器的 0 地址是向量表/ROM，可读**，
   读到 0 就当空串结束；Unicorn 默认不映射 0 页，直接抛
   `UC_ERR_READ_UNMAPPED` 终止整个模拟器。

### 三处修复

| 修复 | 文件 | 作用 |
|---|---|---|
| 映射 64KB 零页 `0x0–0x10000`（全 0）| `vm.py` | 让 Unicorn 行为贴近真机，所有 NULL `%s` 类崩溃一次性兜住 |
| `resolve()` 把 `.`/`..` 归一化并**钳制在 root 内**，不再返回 None | `fs.py` | 从源头不给 ext 递 NULL；`./` 现在正确解析成 root |
| `mr_platEx(1204)` 完整实现 `dsmSwitchPath` | `api/impl.py` | 正确写回 `*output`（`uint8**`）与 `*output_len`（`int32*`），Y/Z/X/A/B/C 分支齐全 |

另加 `UC_HOOK_MEM_INVALID` 诊断钩子：崩溃时打印非法访问地址与 PC，
不用再靠猜。`--strict-null` 可关掉零页映射，专门用于抓 NULL 解引用。

> 取舍：零页映射会**掩盖**一部分真实的 NULL 解引用 bug。对模拟器而言，
> 让 2008 年的老应用继续跑比精确报错更有价值；调试时用 `--strict-null`
> 恢复严格模式。这是刻意选择，不是遗漏。

### 验证

- `tests/net_probe.py::test_rx_regression`：完整加载 `R_Xplore_MTK_all（RX管理器）.mrp`，
  90 步按键（含进入目录、切盘符、返回、数字快捷键）+ 每步 timer，
  **无 `UC_ERR_READ_UNMAPPED`**；日志中 945 次 `dsmSwitchPath` 全部正常。
- 原有 6 套自检全部无回归。

## 7. 用法

```bash
# 默认：网络开启、直连、零页映射开启
python run.py runtime/mythroad/QQDSM2007.mrp --workdir runtime

# 系统开了 Clash，让 MRP 的 TCP 走它（HTTP CONNECT）
python run.py --net-proxy http://127.0.0.1:7890
# 或 set PYMRP_NET_PROXY=http://127.0.0.1:7890

python run.py --net-off          # 完全关网，所有 socket API 返回 MR_FAILED
python run.py --strict-null      # 调试：不映射零页，抓 NULL 解引用
python run.py --stats            # 退出时打印 socket/DNS/回调计数

python tests/net_probe.py        # 57 项，全部本机回环，不需要联网
```

`--net-proxy` 只作用于 **MRP 应用自己的 TCP 连接**；游戏中心拉在线索引
走的是另一套（环境变量 `PYMRP_PROXY` 或自动探测系统代理），互不干扰。

## 8. 已知边界

- 2008 年前后的 MRP 服务器绝大多数已下线，网络通了也不代表能连上；
  本模块的验收标准是**接口语义正确 + 回环 TCP/UDP 实测通过**。
- 只实现 IPv4 TCP/UDP，没有 `mr_bind` / `listen` / `accept`（MRP 侧本来
  就只作客户端）。
- 出站代理只做 HTTP `CONNECT`；SOCKS5 未做（Clash 的 7890 混合端口
  接受 HTTP CONNECT，够用）。
- DNS 用宿主 `gethostbyname`，4s 超时，不模拟当年 cmwap/cmnet 的
  接入点差异；`mode` 只记录不解释。
- `cfunction.ext` 自己内部还实现了一份 `dsmSwitchPath`（日志 `[arm] ...`
  就是它打的），宿主 `mr_platEx(1204)` 主要覆盖直接调桥接表的 MRP；
  两条路径行为一致，不会互相打架。
