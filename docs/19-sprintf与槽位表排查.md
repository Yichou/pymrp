# 19 sprintf、槽位表与 RX 列表里那个 "f"

> 2026-11-10 晚 ~ 11-11 早。老板看到 RX 管理器列表里多出一个字符 **f**（红箭头指着），
> 问：「你是不是没有实现 sprintf」。随后老板补充了两条关键信息：
> ① 「RX 管理器是我开发的，我很清楚这里是调用的 **sprintf 格式化文件大小**」；
> ② 「参考 mrpoid 源码（斯凯官方引擎源码在 `mr` 目录），漏掉的该补补上」。
>
> 最终结论：
>
> * **老板的直觉完全正确**：`%f` 的浮点实参我们**按寄存器取**（错），AAPCS 规定
>   浮点变参**永远走栈** → 读到栈底垃圾 → 屏幕上留下一个 "f"。已按 AAPCS 重写取参，
>   并用**真实 ARM 机器码**验证：`%.1f` 从栈上取到 3.14159 → 输出 "3.1"。
> * **返回值也是错的**：我们返回 Python **字符数**，C 标准要**字节数** —— 中文文件名
>   会让应用定位下一列时错位。已改。
> * **槽位表**：我们此前拿 **mr 层**那张表去比，得出「错位 112 项」的错误结论。
>   实际上我们的 `cfunction.ext` 是 **mythroad 引擎**的扩展，应该对 **mythroad 层**
>   的表 —— 补齐后 **0x000–0x07C 与官方逐项一致**，唯一真缺的是
>   **0x058 的 `mr_stop_ex`**（此前是空位，应用一调就跳地址 0），已补。

## 二、sprintf 的真实状态（修复前）

| 项 | 状态 | 说明 |
|---|---|---|
| `%f` 等浮点 | **取参错** | 按寄存器取浮点实参 → AAPCS 规定浮点变参**永远走栈** → 读到垃圾 |
| `mr_sprintf` | **没实现** | mr 层 C 库表里有它（0x048） |
| `%ld` | **只 32 位** | 长度修饰符的 `l` 被当转换符吃掉 |
| 宽度/精度/对齐 | **基本没做** | 只做了零填充 |
| **返回值** | **错的** | 返回 Python **字符数**，C 标准要**字节数** |

第二条最阴险：`sprintf` 写进内存的是 GBK 字节（`put_cstr` 用 GBK），
但返回值是字符数。文件名里有中文时（老板列表里就有「2012红警战国」），
应用拿返回值定位下一列就会**短一截 → 错位**。

## 三、格式化器补齐清单

`impl.py` 的 `_fmt` 从 60 行的小函数重写成「解析 / 取参 / 渲染」三段：

```python
_parse_fmt(fmt)   -> [{"kind":"text"|"conv", flags, width, prec, lenmod, conv}, ...]
_collect(specs, get_int, get_q, get_f) -> {下标: (类型, 值)}
_render(specs, vals, mem) -> str
```

| 类别 | 支持 |
|---|---|
| 转换符 | `%d %i %u %o %x %X %f %e %g %G %c %s %p %%` |
| 长度修饰符 | `hh h l ll L j z t`（ARM AAPCS：**long 是 32 位**，long long 才 64 位） |
| 标志 | `-`（左对齐）`+`（带号）空格 `#`（0x/0 前缀）`0`（零填充） |
| 宽度/精度 | 数字宽度、`.N` 精度、`*` 动态宽度与精度 |

### 3.1 取参按 AAPCS 变参布局（关键修复）

AAPCS 对**变参函数**的规则：

- 整数/指针参数：前 4 个走 r0–r3，其余走栈（4 字节槽）；
- **`double` 永远走栈**（8 字节、8 字节对齐），不占整数寄存器。

我们的旧实现按 `ctx.arg(2+i)` 一律取寄存器 → `%f` 的实参根本没在寄存器里，
取到的是栈底垃圾 → 格式化结果里留下 "f" 这种残留。

现在 `sprintf` 自己模拟 AAPCS 栈布局：

```python
reg = 2              # 还能用的整数寄存器（r2、r3）
stk = 0              # 栈上已占用字节

def _int():   # 整数：寄存器区用满后走栈（4 字节槽）
def _wide():  # 64 位：寄存器放不下，直接走栈（8 字节对齐）
def _dbl():   # double：永远走栈（8 字节对齐）
```

配套 `bridge.py::ArmCall` 新增 `stack_read / fstack / qstack`（按**字节偏移**
读栈，这是 AAPCS 变参的真实来源）。

### 3.2 返回值改成字节数

`sprintf` 返回**写入的字节数**（不含结尾 null），按 GBK 编码后算。

### 3.3 mr_sprintf

`impl` 里注册 `mr_sprintf`（与 sprintf 同语义）。它属于 **mr 层**那张 C 库表
（0x048），我们的表按 mythroad 层排，所以**不占槽位**，等确认需要时挂上即可。

## 四、槽位表：斯凯有**两张**，别比错对象

这是本次最值得记住的一条。

| 表 | 出处 | 给谁用 | 0x044 | 0x048 | 0x058 |
|---|---|---|---|---|---|
| **mythroad 层** | `mythroad/mythroad.c::_mr_c_function_table` | **斯凯 mythroad 引擎 / DSM 应用（cfunction.ext）** | `mr_sprintf` | `mr_atoi` | `mr_stop_ex` |
| mr 层 | `mr/mythroad.c::_mr_c_function_table` | MRP 应用（另一套栈） | `sprintf` | **`mr_sprintf`** | `NULL` |

mr 层比 mythroad 层**多一个 `mr_sprintf`**（0x048），所以整表往后差一格。
我第一次就是拿 **mr 层**那张表去比我们的，得出「从 0x048 起整表错位一格、
112 项不一致」的结论 —— **比错了对象**。

`cfunction.ext` 是 mythroad 引擎的扩展，所以应该对 **mythroad 层**。逐项核对：

```
  0x000–0x044  malloc/free/realloc/memcpy/…/strlen/strstr/sprintf   ✓ 全一致
  0x048        mr_atoi        → 我们的 atoi                          ✓
  0x04C        mr_strtoul     → 我们的 strtoul                       ✓
  0x050        mr_rand        → 我们的 rand                          ✓
  0x054        NULL(保留)     → 我们的 reserve0（数据槽 0）           ✓
  0x058        mr_stop_ex     → 我们的 reserve1（数据槽 0）  ← ✗ 唯一真缺
  0x05C–0x07C  c_internal / c_port / c_function_new / mr_printf /
               mr_mem_get / mr_mem_free / mr_drawBitmap /
               mr_getCharBitmap / mr_timerStart                      ✓ 全一致
```

### 4.1 补上 mr_stop_ex

官方语义（`mythroad/mythroad.c:716`）：

```c
static int32 mr_stop_ex(int16 freemem)
{
    if (0 == mr_state) return MR_IGNORE;
    if (mr_state == 1 || mr_state == 2) { /* 通知宿主停止 */ }
    mr_state = 0; mr_timer_state = 0; mr_timer_run_without_pause = 0;
    if (0 != freemem) { /* 释放屏幕缓冲 */ }
    return MR_SUCCESS;
}
```

在我们这边等价于「应用请求退出」：置 `vm.exited`，主循环下一帧统一收尾
（停声音 / 关网络 / 关句柄）并退回系统界面。

**此前这一格是 0（空位）** —— 应用一调 `blx` 到地址 0，**整个模拟器直接崩**。
补上后 0x000–0x07C 与官方**逐项一致**。

### 4.2 回归防护

`tests/table_probe.py`（14 项）把三件事钉死：

- 0x000–0x07C 与 **mythroad 官方**逐项对齐（名字比较时忽略 `mr_` / `_` 前缀）；
- 0x048 是 `atoi`（mythroad 层）、0x058 是 `mr_stop_ex`；
- 明确记录**与 mr 层那张表的差异**（0x048/0x04C 两项），避免以后又比错。

## 八、边界与后续

- `qstack/fstack` 按 AAPCS 近似（8 字节对齐取栈）；ARM 上 64 位/浮点变参确实走栈，
  MRP 里极少用到。
- `sprintf` 返回值改成字节数是**行为变化**：若有应用原先依赖字符数会受影响 ——
  但按 C 标准字节数才是对的，且中文场景下字符数必然是错的。
- **rx_env / launcher_probe** 之类依赖真实 `runtime/` 目录的断言要防目录漂移
  （今天新下载的 `abxmain.mrp` 入口是 `cfunction.ext`，曾让 launcher_probe 误报）。
- 官方表差异**已消除**（0x000–0x07C 对齐），0x078 之后的槽位仍是我们自己的
  布局（MR API 部分），继续按 ext 反推维护。
